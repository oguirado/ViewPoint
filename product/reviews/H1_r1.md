## Non-Blocking Backlog

Ranked by severity. None of these breaks the scripted live rehearsal, which drives agents through the H2 SDK with `<run_id>-`-prefixed ASCII ids and UTF-8 shells (`swarm/agents/prompts.py:25-28`).

**R1 (MAJOR, residual B2 class). One intent containing a lone UTF-16 surrogate crashes the broker once.**
- **Cause**: `_emit_event` serialises with `ensure_ascii=False` and then writes UTF-8 (`swarm/broker/broker.py:398-401`). Any agent-controlled string that reaches an event record raises `UnicodeEncodeError` (`surrogates not allowed`). Such strings include `kind`, `expect`, `lane`, `action_class` and `write_set` entries, through `swarm/broker/broker.py:706` → `swarm/broker/broker.py:718-739`, and the `unsupported lane` reason at `swarm/broker/broker.py:1508`.
- **The `script` field crashes differently**: at dispatch, `atomic_write_text` (`swarm/broker/broker.py:932`) or `script.encode` (`swarm/broker/broker.py:892`) raises. That happens after the `turn` record and before any `close`.
- **Probe `B2_lone_surrogate`**: valid JSON `"kind":"\ud800"` gave `CRASH UnicodeEncodeError`. The file was already in `processed/`, and the restart was `ok`. So there is no crash loop, but in-memory FIFOs, seen ids and the nonce are lost.
- **How an agent could reach it**: H2 serialises with the default `ensure_ascii=True` (`swarm/agents/intent_cli.py:374`), so lone surrogates pass through as `\udcXX`. One way to produce them is non-UTF-8 bytes in a CLI argument, which Python decodes with surrogateescape. That is not expected from the rehearsal agents.
- **Fix direction**: serialise events with `ensure_ascii=True`, or reject or sanitise non-encodable strings inside the ingest `try`.

**R2 (MINOR). `event_id` validation uses `re.match` with `$`, which accepts a trailing newline.**
- **Where**: `swarm/broker/broker.py:53` and `swarm/broker/broker.py:243`. H2 has the same pattern at `swarm/agents/intent_cli.py:37` and `swarm/agents/intent_cli.py:260`.
- **Effect**: an id of `ok\n` passes. The broker writes `<nonce>__1__ok\n.py`, which stays inside the inbox, so this is not traversal. The bridge regex then rejects it to `SWARM_REJECTED` as `INVALID_NAME`, confirmed by running the bridge (`rejected: ['…__1__ok\n.py']`).
- **Consequence**: the broker waits the full 120 s script cap, then `TURN_TIMEOUT`, `RECONCILE` and `actuator_busy`, and the queue stalls until the director acts.
- **Fix direction**: use `fullmatch` or `\Z` in both H1 and H2.

**R3 (MINOR, carried from M2/M7). After `reconcile`, a job that timed out can still run unobserved.**
- The timed-out job is deliberately left in the inbox (`swarm/broker/broker.py:968`). The bridge later runs it, and its receipt is never consumed.
- `reconcile` / `checkpoint` clear `actuator_busy` without checking for that receipt or the inbox (`swarm/broker/broker.py:780-797`). So the late scene mutation can land after the reconcile frame with no `scene_epoch` bump.
- `resume` returns to `IDLE` without clearing busy (`swarm/broker/broker.py:766-779`). Every queued intent then burns as `ACTUATOR_BUSY` until a `reconcile`. That is safe, but the director runbook must say `reconcile`, not `resume`, after a timeout.
- §3.3 watchdog / `checkpoint` restore is still not implemented.

**R4 (MINOR). Epoch accounting understates real changes after an uncertain GUI or script outcome.**
- After a GUI timeout with keys already delivered, `view_epoch` is not bumped (`swarm/broker/broker.py:1272-1293`). Probe `M3_mid_key_timeout` gave `view_epoch` 0 after `KP_1` returned rc 0.
- On a post-act or post-script capture failure, the epoch increment is rolled back even though the actuator already changed state (`swarm/broker/broker.py:1046`, `swarm/broker/broker.py:1369`).
- The queue is in `RECONCILE` in every case, so no agent acts on the stale epoch until the director reconciles. Bumping on reconcile, or not rolling back, would be more truthful.

**R5 (MINOR). The lease TTL is effectively unenforced.**
- `_maybe_renew_lease` runs before the expiry comparison (`swarm/broker/broker.py:851-853`), so a lease that has already expired is renewed at dispatch.
- Only `expire_lease()` (`swarm/broker/broker.py:812-817`) can produce `LEASE_EXPIRED` by time.
- This is acceptable for the rehearsal, but it hollows out the §4 TTL semantics.

**R6 (MINOR, H0 contract). The GUI timeout verdict still diverges from §3.1.**
- §3.1 step 4.5 (`swarm/CONTRACT.md:110`) says `INPUT_UNCERTAIN`. The broker emits `TURN_TIMEOUT` (`swarm/broker/broker.py:1288`), which matches §6 (`swarm/CONTRACT.md:264`).
- Both enter `RECONCILE`. However, H2's prompt treats `TURN_TIMEOUT` as "observe, don't flood" rather than "never auto-repeat" (`swarm/agents/prompts.py:46-47`). An agent might re-enqueue keys that were half delivered once the director reconciles.
- H0 should pick one verdict.

**R7 (MINOR, rehearsal tuning). GUI intents tend to hit the stale-frame limit while script agents are active.**
- `auto_rebase_viewport` defaults to off (`swarm/broker/broker.py:290`), and the README live command does not set it (`swarm/broker/README.md:18`).
- `camera-agent` is last in the ring, and a requeued intent keeps its original `based_on_frame` (`swarm/broker/broker.py:1179`). So any frame captured between enqueue and turn makes it reach `drops == 3` within 3 sweeps.
- This follows the contract (§3.1 step 4.3). H2 recovers by re-observing on rc 3 (`swarm/agents/intent_cli.py:671-675`). The recommendation is to launch the rehearsal with `--auto-rebase-viewport` for the view-only key set, or to accept the retries.

**R8 (MINOR, carried m7/m8/m12)**
- `script_sha256: null` is still accepted (`swarm/broker/broker.py:890-891`).
- `v`, `action_class` and `max_acts` are still not validated.
- Seen ids are kept only in memory, so duplicates are not detected across restarts (`swarm/broker/broker.py:357`).
- Frames that leave the ring are never deleted from `/dev/shm` (`swarm/broker/broker.py:509-511`).

**R9 (NIT). The GUI parser only catches `JSONDecodeError` when reading `vision act` stdout.**
- At `swarm/broker/broker.py:1255-1263`, a non-object stdout, or `"receipt": null` when `changed_regions` is empty, would raise `AttributeError` after keys were delivered.
- The current `vis` output always puts `receipt` as an object (`~/Documentos/vis-skill/vis:792`, `~/Documentos/vis-skill/vis:837`), so this is not reachable today.

**R10 (NIT). The bridge returns a non-hex nonce-file value verbatim (`swarm/broker/bridge.py:75`).**
- This is harmless because `JOB_FILENAME_RE` requires a hex nonce, so nothing matches. Returning `""` would be cleaner.
