## Findings

### MAJOR (live path)

**R1. On the live TaskLight room, a failed `close_task` during `--finalize` still exits 0 with `clean: true`.**
- The contract's room is persistent: `~/.context-wall/rooms/viewpoint/events.jsonl`. It already holds two `close` events for each of `modeler-agent`, `props-agent`, `look-agent` and `camera-agent`. They come from the W0 probes on 2026-11-14 (texts `W0 probe ok for …` and `W0 probe passed for …`) [MEASURED, read-only].
- `reconciler.py:219-220` counts any `close` in the room's whole history. It does not check that the close comes after the agent's latest `plan` from the current run. A close from an earlier run therefore satisfies `MISSING_CLOSE_TASK` at `reconciler.py:251-257`.
- `finalize_open_tasks` collects the refusal in `self.last_finalize_errors` (`projector.py:1091-1094`), but `finalize()` (`projector.py:1160-1174`) never uses it. `main()` decides rc from `report.clean` alone (`projector.py:1270-1272`).
- Probe STALE [MEASURED]: the reconciler pointed at a `/tmp` copy of the live room (which is also the default when `CW_HOME` is unset, `reconciler.py:80-82`). A sink whose `close_task` returns `isError: true` for `props-agent` gave `clean=True, anomalies=[], finalize_errors=1`, which means rc 0.
- Probe P1 with `cw_home=None` reached the same result through the default `~/.context-wall`.
- So contract §7.2's negative control ("Reconciler flags any agent with `post_plan` lacking `close_task`") cannot fire in the live rehearsal room. That is the same failure mode as the original M1, through a different path.
- Fix, either option is enough, both are better:
  - (a) In `finalize()`, turn each entry of `last_finalize_errors` into an anomaly (for example `CLOSE_TASK_REFUSED`) and set `clean` to false.
  - (b) In the reconciler, accept a `close` for an agent only if it comes after that agent's latest `plan` in room order (file order or `lamport`).
- Add a test that seeds the room with an earlier `close` before the run.

### Non-Blocking Backlog

- **r1-2.** `sanitize_osb_text` lets DEL (U+007F) through (`projector.py:81`), but `osb` refuses it (`osb:151`). Probe P3: `text has control character U+007F`. Unlikely to appear in broker reasons; add `or code == 127`.
- **r1-3.** A lone surrogate in a decoded `reason` (for example JSON `"\ud800"`) makes `sanitize_osb_text` raise `UnicodeEncodeError` at `projector.py:88`. `run_once` only catches `json.JSONDecodeError` (`projector.py:1128`), so the exception ends the run. Probe P3 [MEASURED]. Encoding with `errors="replace"` or `surrogatepass` and catching per record would contain it.
- **r1-4.** Residual from m5: if a write is split inside a multibyte UTF-8 character, text-mode `readline()` raises `UnicodeDecodeError` at `projector.py:1115`. This kills `run_once` and `--follow` (only `KeyboardInterrupt` is caught, at `1154`). The offset stays at the start of the line, so a restart recovers and nothing is lost. The broker writes `ensure_ascii=False` (`broker.py:399`) in a single `write`, so the race is narrow. Reading in binary and splitting on `b"\n"` removes it.
- **r1-5.** When the MCP returns a JSON-RPC error, `TaskLightMcpSink.call_tool` raises at `projector.py:602-603`. That aborts the `finalize_open_tasks` loop at `1081-1096`, so the remaining agents never get a `close_task` attempt. The run still exits non-zero through the traceback.
- **r1-6.** `MISSING_REF_ON_REFUSAL` still cannot fire. `reconciler.py:150` always builds a non-empty fallback ref, and `extract_park_target` always returns at least `"park"` (`projector.py:108`), so the checks at `reconciler.py:151-158` and `173-178` are vacuous. The README still presents it as a live check (`README.md:128`).
- **r1-7.** Still open from the H4 review: m7 (classifying refusals against contract §6 is undocumented, `projector.py:40-54`); the second part of m8 (SIGTERM skips the final save and `--finalize`, `projector.py:1154`); n4 (`--once` has no effect, `projector.py:1219-1223`); n5 (MCP stderr is never drained and `_read_raw` has no timeout, `projector.py:541-586`); n8 (auto-open against the live `sbd` is not verified: AUSENTE — no inventar).
