# `vp vision`: see and drive a GUI on a private display

Wraps the vision skill: start an application on its own private display, look (screenshot with numbered marks), act (click, type, key) with a verified visible change, check a state, stop. Use it for Blender and any desktop, Electron or web GUI that is not a ViewPoint browser capsule.

Generated by `docs/build_pages.py` from `design/MCP_TOOLS.json` (vpops/1.4), `docs/family_notes.json` and `router/seeds.jsonl`. For exact file:line citations with freshness marks run `vp docs ask "<question>"`.

## Commands

| Command | Class | What it does | Wraps |
|---|---|---|---|
| `vp vision doctor` | R (read-only) | Check the vision engines. | `$VP_VISION doctor` |
| `vp vision start` | X (starts a process) | Start an app, web page or Electron dir on a private display under a job name. | `$VP_VISION start --job J (--app CMD / --web URL / --electron DIR) [--size WxH] [--wait-title T] [--mem M]` |
| `vp vision look` | R (read-only) | Capture a frame and numbered marks of the job. | `$VP_VISION look --job J` |
| `vp vision act` | W (write-own) | One input act (click mark, xy, type, key) with an expected change. | `$VP_VISION act --job J (--click N / --xy X,Y / --type T / --key K / --ax REF) [--expect-change KIND]` |
| `vp vision check` | R (read-only) | Read back a state: DOM/AX state, absent state or window title. | `$VP_VISION check --job J (--state S / --state-absent S / --window-title T)` |
| `vp vision stop` | D (destructive, needs `--confirm`) | Stop one vision job and its processes (by recorded pid + start time). | `$VP_VISION stop --job J [--keep-frames]` |
| `vp vision sweep` | D (destructive, needs `--confirm`) | Collect vision jobs whose target died. Only jobs in this session's ledger unless foreign_ok. | `$VP_VISION sweep` |

## Arguments, confirm ids and codes

- `vp vision doctor` MCP tool `vp_vision_doctor` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `DEPENDENCY` rc 8.
- `vp vision start --job [--app] [--web] [--electron] [--size] [--wait-title] [--mem]` MCP tool `vp_vision_start` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `FORBIDDEN_DISPLAY` rc 3, `TIMEOUT` rc 124.
  - `--job` (string, required): job name; new jobs must start with VP_JOB_PREFIX (vpops)
  - `--app` (string): command line of a desktop app
  - `--web` (string): URL
  - `--electron` (string): Electron app dir
  - `--size` (string): WxH, default 1280x800
  - `--wait-title` (string): window title to wait for
  - `--mem` (string): memory cap, e.g. 8G
- `vp vision look --job [--foreign-ok]` MCP tool `vp_vision_look` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `FOREIGN_JOB` rc 3, `NOT_FOUND` rc 5.
  - `--job` (string, required): job name; new jobs must start with VP_JOB_PREFIX (vpops)
  - `--foreign-ok` (string): explicit permission to act on one job this session did not start
- `vp vision act --job [--click] [--xy] [--type] [--key] [--ax] [--expect-change] [--foreign-ok]` MCP tool `vp_vision_act` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `ACT_BUSY` rc 6, `STALE_FRAME` rc 7, `INPUT_UNCERTAIN` rc 7, `FOREIGN_JOB` rc 3.
  - `--job` (string, required): job name; new jobs must start with VP_JOB_PREFIX (vpops)
  - `--click` (integer): mark number from the last look
  - `--xy` (string): X,Y
  - `--type` (string): text to type
  - `--key` (string): key chord, e.g. ctrl+s
  - `--ax` (string): accessibility ref
  - `--expect-change` (string): any (default), none, exit
  - `--foreign-ok` (string): explicit permission to act on one job this session did not start
- `vp vision check --job [--state] [--state-absent] [--window-title] [--foreign-ok]` MCP tool `vp_vision_check` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `CHECK_FALSE` rc 1, `FOREIGN_JOB` rc 3.
  - `--job` (string, required): job name; new jobs must start with VP_JOB_PREFIX (vpops)
  - `--state` (string): e.g. button=Done
  - `--state-absent` (string): state that must not be present
  - `--window-title` (string): expected title
  - `--foreign-ok` (string): explicit permission to act on one job this session did not start
- `vp vision stop --job [--keep-frames] [--foreign-ok]` `--confirm <id>`: required unless dry_run: must equal the job name. MCP tool `vp_vision_stop` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `CONFIRM_REQUIRED` rc 4, `FOREIGN_JOB` rc 3, `NOT_FOUND` rc 5.
  - `--job` (string, required): job name; new jobs must start with VP_JOB_PREFIX (vpops)
  - `--keep-frames` (boolean): keep the frame files
  - `--foreign-ok` (string): explicit permission to act on one job this session did not start
- `vp vision sweep [--foreign-ok]` `--confirm <id>`: required unless dry_run: must equal the literal `sweep`. MCP tool `vp_vision_sweep` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `CONFIRM_REQUIRED` rc 4.
  - `--foreign-ok` (string): explicit permission to act on one job this session did not start

Every command also accepts `--dry-run` (code `DRY_RUN`, nothing starts) and `--timeout-s S` (code `TIMEOUT`, rc 124).

## Typical sequence

```sh
vp vision doctor
vp vision start --job vpops-demo --app "xclock" --wait-title xclock
vp vision look --job vpops-demo
vp vision act --job vpops-demo --click 3
vp vision check --job vpops-demo --state "button=Done"
vp vision stop --job vpops-demo --confirm vpops-demo
```

## Rules and traps

- Always stop the job you started, also after a failure.
- After a failed `act` the marks are invalid: run `vp vision look` again before the next `act`.
- Upstream rc 3 (expected change missed): look again and diagnose; do not repeat the same action blindly.
- `ACT_BUSY` (rc 6): another act held the job for 10 s; wait and retry once.
- An `act` pass proves only that something changed. Acceptance needs a `vp vision check` pass or the frame you read.
- Never drive display `:1`, the operator display or a job of another session (`FORBIDDEN_DISPLAY`, `FOREIGN_JOB`).
- `vp vision sweep` stops every vision job of this user: class D, `--confirm sweep`, and only when the operator asks.

- (failure) vision exit codes: 0 condition passed (still verify meaning), 2 bad call/unknown job/reused passed step, 3 expected change missed, 4 three attempts on this step, 5 safety rule refused (do not bypass), 6 RAM/time/lock budget, 7 capability absent, 8 target died or froze, 9 internal error. Source: `~/.claude/skills/vision/SKILL.md`.
- (invariant) An `act` pass proves only its declared visible change; acceptance needs a `check` pass receipt or the frame you read cited by `frame_sha256`; `look`/`stop` receipts are not acceptance. Source: `~/.claude/skills/vision/SKILL.md`.
- (invariant) Always `vision stop`, even after failure, and cite the receipt path it prints; never drive an inherited or person-owned display, and frames stay in `/dev/shm/vqa-cu/vis/<job>/`, never on disk. Source: `~/.claude/skills/vision/SKILL.md`.
