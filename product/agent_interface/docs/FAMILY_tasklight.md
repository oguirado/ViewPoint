# `vp tasklight`: the TaskLight wall (context-wall cards)

Starts the TaskLight wall for ViewPoint rooms and posts or reads cards (status, plan, step, close). Agents in Antigravity can also use the `context-wall` MCP server directly.

Generated by `docs/build_pages.py` from `design/MCP_TOOLS.json` (vpops/1.4), `docs/family_notes.json` and `router/seeds.jsonl`. For exact file:line citations with freshness marks run `vp docs ask "<question>"`.

## Commands

| Command | Class | What it does | Wraps |
|---|---|---|---|
| `vp tasklight check` | R (read-only) | Readiness table of the TaskLight wall and its MCP server. | `cd $VP_TASKLIGHT && node tools/demo/run_tasklight.mjs --check --headless` |
| `vp tasklight start` | H (human-facing) | Start the TaskLight wall for ViewPoint rooms. Pass no_observer when the agents or the projection post the cards. | `cd $VP_TASKLIGHT && node tools/demo/run_tasklight.mjs --viewpoint [--no-observer] [--headless]` |
| `vp tasklight post` | W (write-own) | Post one card act to a TaskLight room: status, plan, step or close. | `cd $VP_TASKLIGHT && python3 -m bridge.room post --room R --agent A --act ACT --text T [--plan-file F] [--step-json J]` |
| `vp tasklight read` | R (read-only) | Read a TaskLight room. | `cd $VP_TASKLIGHT && python3 -m bridge.room read --room R [--since N] --json` |

## Arguments, confirm ids and codes

- `vp tasklight check` MCP tool `vp_tasklight_check` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `FAIL` rc 1, `DEPENDENCY` rc 8.
- `vp tasklight start [--no-observer] [--headless]` MCP tool `vp_tasklight_start` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `FAIL` rc 1.
  - `--no-observer` (boolean): wall only: cards come from cooperative agents (`tasklight post` or `projection run`)
  - `--headless` (boolean): no window
- `vp tasklight post --room --agent --act --text [--plan-file] [--step-json]` MCP tool `vp_tasklight_post` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2.
  - `--room` (string, required): room slug
  - `--agent` (string, required): agent id; the 4-agent capsule uses modeler-agent, props-agent, look-agent, camera-agent
  - `--act` (string, required): status, plan, step or close
  - `--text` (string, required): short text
  - `--plan-file` (string): JSON plan for act=plan
  - `--step-json` (string): JSON of one step for act=step
- `vp tasklight read --room [--since]` MCP tool `vp_tasklight_read` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2.
  - `--room` (string, required): room slug
  - `--since` (integer): only events with Lamport/offset greater than this

Every command also accepts `--dry-run` (code `DRY_RUN`, nothing starts) and `--timeout-s S` (code `TIMEOUT`, rc 124).

## Typical sequence

```sh
vp tasklight check
vp tasklight start --no-observer
vp tasklight post --room viewpoint --agent modeler-agent --act status --text "building the nucleus"
vp tasklight read --room viewpoint
```

## Rules and traps

- With cooperative agents start with `--no-observer`, so each capsule shows one card, not two.
- Never put typed text, passwords, tokens, cookies or page content into a title, step, outcome or status.
- An expected ViewPoint refusal is a step that is done with outcome "refused as expected", not a blocked step.
