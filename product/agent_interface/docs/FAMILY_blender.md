# `vp blender`: live Blender with a script bridge

Starts Blender on a private display with a bridge that executes Python scripts inside the live session, runs scripts through it, verifies exported `.glb` files headless, and stops the job. Scripts change the scene; the GUI stays visible for the recording.

Generated by `docs/build_pages.py` from `design/MCP_TOOLS.json` (vpops/1.4), `docs/family_notes.json` and `router/seeds.jsonl`. For exact file:line citations with freshness marks run `vp docs ask "<question>"`.

## Commands

| Command | Class | What it does | Wraps |
|---|---|---|---|
| `vp blender start` | X (starts a process) | Start Blender with a script bridge under a vision job. bridge=ref uses RT/inbox with a nonce; bridge=hybrid uses the playbook bridge and needs allow_hybrid. | `$VP_VISION start --job J --size 1920x1080 --mem 8G --app 'blender --factory-startup --python <bridge.py>' --wait-title Blender; bridge = $VP_REF/ref_broker/bridge.py (VP_SWARM_RT, VP_SWARM_NONCE) or $VP_HOME/hackathon/playbooks/blender_hybrid/blender_bridge.py` |
| `vp blender exec` | W (write-own) | Run one bpy script inside the live Blender of the hybrid playbook lane (bridge=hybrid, needs allow_hybrid) and return OK/ERROR plus bounded output. With bridge=ref the bridge only runs nonce-carrying files from the broker: the command answers NOT_FOUND and `next` points at `vp queue enqueue` + `vp queue run --turns 1`. | `hybrid: $VP_HOME/hackathon/playbooks/blender_hybrid/bpy_live SCRIPT.py; ref: write RT/inbox/<nonce>_<id>.py atomically, read RT/outbox/<id>.out` |
| `vp blender verify` | R (read-only) | Import a .glb in a separate headless Blender under a memory cap and report object, mesh and material counts. | `systemd-run --user --scope -q -p MemoryHigh=6G -p MemoryMax=8G -p MemorySwapMax=0 timeout 120 blender -b --factory-startup --python <verify from verify_glb_template.py>` |
| `vp blender stop` | D (destructive, needs `--confirm`) | Stop the Blender job (alias of `vision stop` that also closes the bridge inbox). | `$VP_VISION stop --job J` |

## Arguments, confirm ids and codes

- `vp blender start --job [--rt] [--bridge] [--size] [--mem] [--allow-hybrid]` MCP tool `vp_blender_start` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `FORBIDDEN_PATH` rc 3, `FORBIDDEN_DISPLAY` rc 3, `TIMEOUT` rc 124.
  - `--job` (string, required): job name; new jobs must start with VP_JOB_PREFIX (vpops)
  - `--rt` (string): runtime root of the multi-agent capsule (VP_SWARM_RT); never under /dev/shm/vqa-cu/hybrid/ without allow_hybrid
  - `--bridge` (string): ref (default) or hybrid
  - `--size` (string): WxH, default 1920x1080
  - `--mem` (string): memory cap, default 8G
  - `--allow-hybrid` (boolean): explicit permission to use /dev/shm/vqa-cu/hybrid/
- `vp blender exec --job --script [--rt] [--bridge] [--budget-s] [--allow-hybrid]` MCP tool `vp_blender_exec` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `FORBIDDEN_PATH` rc 3, `NOT_FOUND` rc 5, `STATE` rc 7, `TIMEOUT` rc 124.
  - `--job` (string, required): job name; new jobs must start with VP_JOB_PREFIX (vpops)
  - `--script` (string, required): path of the bpy script
  - `--rt` (string): runtime root of the multi-agent capsule (VP_SWARM_RT); never under /dev/shm/vqa-cu/hybrid/ without allow_hybrid
  - `--bridge` (string): ref (default) or hybrid
  - `--budget-s` (number): self-enforced time budget added through ref_agents/guard.py
  - `--allow-hybrid` (boolean): explicit permission to use /dev/shm/vqa-cu/hybrid/
- `vp blender verify --glb` MCP tool `vp_blender_verify` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `FAIL` rc 1, `TIMEOUT` rc 124.
  - `--glb` (string, required): path of the exported .glb
- `vp blender stop --job [--foreign-ok]` `--confirm <id>`: required unless dry_run: must equal the job name. MCP tool `vp_blender_stop` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `CONFIRM_REQUIRED` rc 4, `FOREIGN_JOB` rc 3.
  - `--job` (string, required): job name; new jobs must start with VP_JOB_PREFIX (vpops)
  - `--foreign-ok` (string): explicit permission to act on one job this session did not start

Every command also accepts `--dry-run` (code `DRY_RUN`, nothing starts) and `--timeout-s S` (code `TIMEOUT`, rc 124).

## Typical sequence

```sh
vp blender start --job vpops-blender --rt /dev/shm/vqa-cu/vpops-rt
vp blender exec --job vpops-blender --rt /dev/shm/vqa-cu/vpops-rt --script build_atom.py
vp vision look --job vpops-blender
vp blender verify --glb out/atom.glb
vp blender stop --job vpops-blender --confirm vpops-blender
```

## Rules and traps

- `/dev/shm/vqa-cu/hybrid/` belongs to the hybrid lane of another session: any path under it is refused (`FORBIDDEN_PATH`) unless you pass `--allow-hybrid` on the operator's instruction.
- The bridge executes any Python file placed in its inbox, without a sandbox. Keep the runtime root private and send only scripts you wrote or read.
- `/dev/shm` is erased on reboot: copy deliverables out when the run ends.
- Blender runs with an 8 GiB memory cap; headless checks run inside `systemd-run --user --scope -p MemoryHigh=6G -p MemoryMax=8G -p MemorySwapMax=0`.
- `vision act` cannot drag the mouse: orbit the view with numpad keys.
