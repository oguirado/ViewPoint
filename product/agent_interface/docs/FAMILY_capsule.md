# `vp capsule`: the ViewPoint take (browser capsules on screen :98)

Starts, inspects, shows and stops the ViewPoint take: the app with its browser capsules on the private X display :98. It wraps `ctl/vp_demo_take.sh`. Use it before any `vp browser` or `vp identity` command.

Generated by `docs/build_pages.py` from `design/MCP_TOOLS.json` (vpops/1.4), `docs/family_notes.json` and `router/seeds.jsonl`. For exact file:line citations with freshness marks run `vp docs ask "<question>"`.

## Commands

| Command | Class | What it does | Wraps |
|---|---|---|---|
| `vp capsule start` | D (destructive, needs `--confirm`) | Fresh restart of the ViewPoint take on screen :98 (4 browser capsules, 2x2, preflight per capsule). It stops a running take first, hence class D. | `bash $VP_HOME/ctl/vp_demo_take.sh start` |
| `vp capsule stop` | D (destructive, needs `--confirm`) | Clean stop of the take; identities and logins are kept. | `bash $VP_HOME/ctl/vp_demo_take.sh stop` |
| `vp capsule status` | R (read-only) | Is a take running; which capsules, which viewer is open. | `stat /tmp/.X11-unix/X98 + viewer pid file + vp_mcp vp_list_capsules` |
| `vp capsule list` | R (read-only) | List configured capsules mapped to core surfaces. | `vp_mcp tools/call vp_list_capsules` |
| `vp capsule view` | H (human-facing) | Open the :98 screen on the operator desktop (localhost VNC, input allowed for manual logins). | `bash $VP_HOME/ctl/vp_demo_take.sh view` |
| `vp capsule show` | H (human-facing) | Show the take as a native window (xpra). Upstream keeps it on HOLD unless VP_SHOW_OK=1. | `bash $VP_HOME/ctl/vp_demo_take.sh show (or vp_mcp vp_show)` |
| `vp capsule hide` | H (human-facing) | Hide the window or viewer; the program keeps running. | `bash $VP_HOME/ctl/vp_demo_take.sh hide (or vp_mcp vp_hide)` |

## Arguments, confirm ids and codes

- `vp capsule start [--ids] [--screen] [--no-preflight]` `--confirm <id>`: required unless dry_run: must equal the literal `take`. MCP tool `vp_capsule_start` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `CONFIRM_REQUIRED` rc 4, `FAIL` rc 1, `NO_TAKE` rc 5.
  - `--ids` (string): comma list of identities (VP_IDS), default arxiv,gemini,github,wikipedia
  - `--screen` (string): WxH of the take screen (VP_SCREEN)
  - `--no-preflight` (boolean): skip the per-capsule checks (sets PREFLIGHT=0)
- `vp capsule stop` `--confirm <id>`: required unless dry_run: must equal the literal `take`. MCP tool `vp_capsule_stop` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `CONFIRM_REQUIRED` rc 4.
- `vp capsule status` MCP tool `vp_capsule_status` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `NO_TAKE` rc 5.
- `vp capsule list` MCP tool `vp_capsule_list` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `NO_TAKE` rc 5.
- `vp capsule view` MCP tool `vp_capsule_view` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `NO_TAKE` rc 5.
- `vp capsule show` MCP tool `vp_capsule_show` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `HOLD` rc 3, `NO_TAKE` rc 5.
- `vp capsule hide` MCP tool `vp_capsule_hide` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2.

Every command also accepts `--dry-run` (code `DRY_RUN`, nothing starts) and `--timeout-s S` (code `TIMEOUT`, rc 124).

## Typical sequence

```sh
vp capsule status
vp capsule start --dry-run
vp capsule start --confirm take
vp capsule list
vp capsule view            # operator watches through VNC
vp capsule hide
vp capsule stop --confirm take
```

## Rules and traps

- `vp capsule start` is class D: the launcher stops a running take before it starts a new one. Run `vp capsule status` first and ask before replacing a take somebody is using.
- After `start`, wait about 1 minute before the first browser command; after switching capsules back to agents wait at least 70 s. Acting earlier gives `STALE_FRAME`.
- `vp capsule show` returns `HOLD` (rc 3): the launcher keeps `show` on hold. Use `vp capsule view`.
- Do not move or click the :98 window while `start` runs: the launcher clicks fixed coordinates.
- `stop` keeps identities and logins; it moves the run directory aside instead of deleting it.

- (config) Env var defaults in the code: CAND=cand10d (the header comment wrongly says cand9) and VP_IDS=arxiv,gemini,github,wikipedia. VP_IDS is sorted and deduplicated, and the first id opens automatically. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.

- (config) VP_STORE defaults to ~/.local/state/viewpoint-demo/identities (private, 0700, outside the repo). Identities and logins persist there across stop/start. PREFLIGHT=0 skips the checks. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (invariant) The take runs on X display :98. When start succeeds it screenshots :98 to tiles.png and prints "READY: take dir $OUT (screen :98). Stop with: bash ctl/vp_demo_take.sh stop". Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (trap) `start` clicks through the GUI with hard-coded xdotool coordinates. It first pins the main window to 1280x720 at 160,140, so do not move or touch the :98 window while start is running. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (invariant) An active lease left behind by a crashed app blocks opening that identity. `start` releases it with `python3 -B $REPO_DIR/tools/mv_identity.py release --id <id> --holder <holder>`, using the newest old state dir. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (contract) `start` writes the MCP session file to /tmp/claude-$UID/vparm64/vp_mcp_session.json with env_launcher, srf_bin, state_dir, repo, xdg_state "/dev/shm/vqa-cu/vp-mwrun", attach_env and capsules [{identity,container,window:"w1"}]. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (invariant) Preflight (default PREFLIGHT=1) first calls vp_navigate on the unknown identity "no-such-id", which must be refused. It then navigates each capsule to its home URL and logs to preflight.jsonl. "NO (oracle broken)" means the refusal check failed. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (command) `bash ctl/vp_demo_take.sh stop` sends SIGTERM to the main chromium in every srf-id-* container so no "Restore pages?" bubble appears next time. It then waits 4 s, runs `xpra exit :98` and runs ctl/vp_demo_v1.sh stop with a 120 s timeout. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (invariant) `stop` moves /tmp/claude-$UID/vparm64 to /tmp/claude-$UID/vparm64.take-HHMMSS rather than deleting it. With no run dir it prints "nothing running" and returns 0. Identities and logins stay in VP_STORE. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (command) `bash ctl/vp_demo_take.sh view` starts x11vnc on :98 (localhost port 5998, no password, input allowed for manual logins). It opens remmina on OPERATOR_DISPLAY (default :0) and saves both PIDs to /tmp/claude-$UID/viewer98.pids. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (failure) `view` exits 1 with "no take running" when /tmp/.X11-unix/X98 does not exist. If a viewer is already open it prints "viewer already open" and exits 0. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (trap) `bash ctl/vp_demo_take.sh show` is on HOLD: unless VP_SHOW_OK=1 it exits 3. The first desktop xpra attach took no input and disturbed the operator's terminal, so use `view` instead. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.
- (command) With VP_SHOW_OK=1, `show` starts an xpra server over the existing :98 if needed (--use-display=yes). It then attaches it seamlessly on OPERATOR_DISPLAY (default :0) and writes the PID to /tmp/claude-$UID/xpra98/attach.pid. Source: `$VP_OPS_ROOT/ViewPoint/ctl/vp_demo_take.sh`.

- (trap) A `systemd-run --user --scope -p MemoryMax=8G` wrapped around `docker run` limits the docker client process, not the container; per-container flags are the limits that apply. Source: `product/ref_capsule/README.md`.
