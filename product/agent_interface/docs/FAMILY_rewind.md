# `vp rewind`: checkpoints and rollback of a multi-agent capsule

Marks named restore points of the program state and returns to one after a wrong edit. A rewind raises the scene epoch, so intents based on older frames close as `STALE_FRAME`. `status` and `audit` only read `events.jsonl`.

Generated by `docs/build_pages.py` from `design/MCP_TOOLS.json` (vpops/1.4), `docs/family_notes.json` and `router/seeds.jsonl`. For exact file:line citations with freshness marks run `vp docs ask "<question>"`.

## Typical sequence

```sh
vp rewind checkpoint --job vpops-blender --rt $RT --label before-electrons
vp rewind status --rt $RT
vp rewind restore --job vpops-blender --rt $RT --to last_good --dry-run
vp rewind restore --job vpops-blender --rt $RT --to last_good --resume --confirm last_good
vp rewind audit --rt $RT
```

## Rules and traps

- `vp rewind restore` discards the work done after the point: class D, `--confirm` must equal the value of `--to`.
- `FROZEN` is left only by a restore to `last_good` followed by resume (`--resume` does both).
- After a restore, every agent must observe again before it enqueues: old frames are stale.
- `vp rewind audit` returns `AUDIT_VIOLATIONS` (rc 1) when the event log breaks a rule; `data.violations` lists them.

## Facts from the wrapped tools

Each fact is pinned to a source line; `vp docs ask` returns the line and whether it is still FRESH.

- (contract) rewind.py's RewindSession sends rewind_request/v0.2 pause/resume/mark/restore over the existing guest-command IO owner and performs no native actions. Each operation's timeout_ms defaults to 30000. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/rewind.py`.
- (invariant) Rewind phase gates: pause only from ready; resume only from paused; mark from ready or paused; restore from paused or recoverable. Anything else raises "operation not admitted in current phase". Source: `$VP_REPO_ROOT/agents/metaviewer_agents/rewind.py`.
- (invariant) In the recoverable phase, restore is accepted only for the session's last_good_usable point. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/rewind.py`.
- (trap) The rewind point ring holds 2 points. A new mark permanently evicts the oldest point that has no active references (lowest created_order). Source: `$VP_REPO_ROOT/agents/metaviewer_agents/rewind.py`.
- (failure) A rewind deadline or a core outcome_unknown event puts the session in the uncertain phase and fails pending operations with GuestCommandUnknown. There is no replay, and commands stay blocked until recovery_ready arrives. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/rewind.py`.
- (command) R4 drives the rewindable capsule with `VP_SWARM_NONCE=<nonce> rewindctl.py run --job J --rt RT --turns N` (rc 0 idle, 3 FROZEN/RECONCILE); `mark` takes a director checkpoint. Source: `product/ref_rewind_demo/rewindctl.py`.
- (command) Leave FROZEN with `VP_SWARM_NONCE=<nonce> rewindctl.py rewind --job J --rt RT --to last_good [--resume]`. Source: `product/ref_rewind_demo/rewindctl.py`.
- (command) `rewindctl.py audit --rt RT | --events F` replays events.jsonl: rc 0 clean, 1 violations, 2 unreadable; `status`, `audit` and `emit-script` never touch Blender, vision or the nonce. Source: `product/ref_rewind_demo/rewindctl.py`.
- (contract) `scene_epoch` starts at 1, +1 per `control rewind`, never decreases; after a bump every queued gui intent closes `STALE_FRAME`. Source: `product/ref_rewind/CONTRACT.md`.
- (invariant) `FROZEN` is left only by `rewind(to=last_good, by="director")` followed by `control resume`; `resume` alone, a rewind to another point, or `by` other than `director` raise `BrokerError`; attempts are capped at `K_MAX = 3` per event id. Source: `product/ref_rewind_lanes/README.md`.
- (trap) `load_ui=True` on `restore_script` is required for a camera GUI turn to be inside the rollback domain; call `st.verify(point)` (CKPT_CORRUPT / CKPT_MISSING) before every restore. Source: `product/ref_rewind_ckpt/README.md`.
