# `vp engine`: the core protocol: observe, propose, wait-verify, bounded runs

Low-level access to the ViewPoint core through `mvctl` and `mw_run`. Prefer `vp browser` for browser capsules; use `vp engine` when you need a single proposal or a program capsule run.

Generated by `docs/build_pages.py` from `design/MCP_TOOLS.json` (vpops/1.4), `docs/family_notes.json` and `router/seeds.jsonl`. For exact file:line citations with freshness marks run `vp docs ask "<question>"`.

## Commands

| Command | Class | What it does | Wraps |
|---|---|---|---|
| `vp engine observe` | R (read-only) | Observe one core surface (frame reference and state) through mvctl. | `python3 -m metaviewer_agents.mvctl (cwd $VP_HOME/repo/agents; --socket --session-id --agent-instance --core-instance --timeout-ms --max-line-bytes --max-reply-bytes from the session file) observe --surface-id S` |
| `vp engine list` | R (read-only) | List core surfaces, paged. | `python3 -m metaviewer_agents.mvctl (cwd $VP_HOME/repo/agents; --socket --session-id --agent-instance --core-instance --timeout-ms --max-line-bytes --max-reply-bytes from the session file) list --limit N [--cursor C]` |
| `vp engine propose` | W (write-own) | Submit one action envelope to the core and return its verdict. | `python3 -m metaviewer_agents.mvctl (cwd $VP_HOME/repo/agents; --socket --session-id --agent-instance --core-instance --timeout-ms --max-line-bytes --max-reply-bytes from the session file) propose --surface-id S --json-arg FILE` |
| `vp engine wait-verify` | R (read-only) | Wait for the verification verdict of a proposal. | `python3 -m metaviewer_agents.mvctl (cwd $VP_HOME/repo/agents; --socket --session-id --agent-instance --core-instance --timeout-ms --max-line-bytes --max-reply-bytes from the session file) wait-verify --surface-id S --proposal-id P` |
| `vp engine run` | W (write-own) | Run the bounded goal runner on a browser or program surface. | `python3 -m metaviewer_agents.mw_run --identity I --surface-kind browser/program --goal G [--text T] [--key K] --steps N --timeout-ms MS --planner rules/muse` |

## Arguments, confirm ids and codes

- `vp engine observe --surface-id [--session]` MCP tool `vp_engine_observe` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `NO_TAKE` rc 5, `TIMEOUT` rc 124.
  - `--surface-id` (string, required): core surface id
  - `--session` (string): absolute path of the vp_mcp session file (VP_MCP_SESSION); default: newest take's session
- `vp engine list [--limit] [--cursor] [--session]` MCP tool `vp_engine_list` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2.
  - `--limit` (integer): page size (default 16)
  - `--cursor` (string): cursor from the previous page
  - `--session` (string): absolute path of the vp_mcp session file (VP_MCP_SESSION); default: newest take's session
- `vp engine propose --surface-id --json-arg [--session]` MCP tool `vp_engine_propose` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `INPUT_UNCERTAIN` rc 7, `TIMEOUT` rc 124.
  - `--surface-id` (string, required): core surface id
  - `--json-arg` (string, required): file holding exactly one envelope
  - `--session` (string): absolute path of the vp_mcp session file (VP_MCP_SESSION); default: newest take's session
- `vp engine wait-verify --surface-id --proposal-id [--session]` MCP tool `vp_engine_wait_verify` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `TIMEOUT` rc 124.
  - `--surface-id` (string, required): core surface id
  - `--proposal-id` (string, required): id returned by engine propose
  - `--session` (string): absolute path of the vp_mcp session file (VP_MCP_SESSION); default: newest take's session
- `vp engine run --identity [--surface-kind] --goal [--text] [--key] [--steps] [--timeout-ms] [--planner]` MCP tool `vp_engine_run` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `INPUT_UNCERTAIN` rc 7, `TIMEOUT` rc 124, `BUSY` rc 6.
  - `--identity` (string, required): capsule identity id, e.g. wikipedia
  - `--surface-kind` (string): browser (default) or program
  - `--goal` (string, required): goal; program mode also accepts focused, focused-key
  - `--text` (string): short text
  - `--key` (string): Enter, Up, Down, Left, Right (browser: only Enter)
  - `--steps` (integer): 1..16
  - `--timeout-ms` (integer): 1..30000
  - `--planner` (string): rules or muse

Every command also accepts `--dry-run` (code `DRY_RUN`, nothing starts) and `--timeout-s S` (code `TIMEOUT`, rc 124).

## Typical sequence

```sh
vp engine list --limit 16
vp engine observe --surface-id <surface>
vp engine propose --surface-id <surface> --json-arg proposal.json
vp engine wait-verify --surface-id <surface> --proposal-id <id>
vp engine run --identity wikipedia --surface-kind browser --goal "search" --text "hydrogen" --key Enter --steps 6
```

## Rules and traps

- A proposal must cite the frame it was based on. If the frame changed, the core refuses with `STALE_FRAME` and nothing is sent: observe again and propose again.
- After a proposal was admitted, a failed or timed-out `wait-verify` is `INPUT_UNCERTAIN`: observe before anything else; never send the same proposal again.
- `mw_run` rc 5 with `INPUT_UNCERTAIN` and rc 6 `MW_WALL_DEADLINE` are final for that run: do not replay.

## Facts from the wrapped tools

Each fact is pinned to a source line; `vp docs ask` returns the line and whether it is still FRESH.

- (command) `python3 -B -m metaviewer_agents.mvctl <observe|list|propose|wait-verify|record-start|record-stop> --socket S --session-id ID --agent-instance A --core-instance C --timeout-ms N --max-line-bytes N --max-reply-bytes N`. All 7 flags are required. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mvctl.py`.
- (contract) mvctl per-verb flags: observe needs --surface-id only; list needs --limit (--cursor optional); propose, record-start and record-stop need --json-arg; wait-verify needs --proposal-id and --json-arg (the expectation). Any other combination is refused with usage_error. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mvctl.py`.
- (config) mvctl --config defaults to $MV_CORE_CONFIG (the trusted registration). session_id and the agent/core endpoints must match it, or the call is refused with usage_error. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mvctl.py`.
- (contract) mvctl exit codes: 0 means the result JSON is on stdout. 1 means a core refusal, printed to stdout as {"verdict":"refuse","reason_code":...} (e.g. STALE_FRAME), or a failed wait-verify receipt. 2 means a local refusal record on stderr. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mvctl.py`.
- (failure) An rc 2 refusal is {"verdict":"refuse","code":...,"error":...} on stderr. Codes: usage_error, input_error, schema_error, unknown_version, endpoint_error, transport_unavailable, transport_error, timeout, unexpected_reply, unsupported_operation, version. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mvctl.py`.
- (contract) An mvctl propose --json-arg file must hold one strict action_proposal/v0.2 JSON object (no duplicate keys, no NaN, size within --max-line-bytes). Any other schema is refused with unknown_version. A repeated flag is refused as a duplicate option. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mvctl.py`.
- (command) Program mode: `python3 -B -m metaviewer_agents.mw_run --surface-kind program --identity ID --goal TEXT --steps N` (steps 1..16, --timeout-ms 1..30000). It records bounded verified visual clicks and makes no task-completion claim. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mw_run.py`.
- (contract) Browser mode without --goal requires --site and --workflow, with every program option left at its default (--steps 1, --timeout-ms 10000, --planner rules). In goal mode --site, --workflow and --slot are rejected. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mw_run.py`.
- (contract) In mw_run browser goal mode --key supports only Enter, and --key requires an explicit --text. --steps must be at least 2, or at least 3 with --key, to cover focus, type and the optional key. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mw_run.py`.
- (contract) In mw_run program mode, --key (Enter/Up/Down/Left/Right) is allowed only with --goal focused-key --steps 1 --planner rules and no --text. Program --text requires --steps 1. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mw_run.py`.
- (failure) mw_run exits with rc 6 and verdict_code MW_WALL_DEADLINE when the run-level wall deadline expires (360 s ceiling). It still writes report.json and the metaviewer.mw_run/v1 JSON line. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mw_run.py`.
- (trap) mw_run rc 5 with verdict_code INPUT_UNCERTAIN means the input may already have been delivered. It is kept even when the deadline expires, so never retry: observe first. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mw_run.py`.
- (config) The env var MV_MW_WALL_DEADLINE_S can only lower the computed wall budget (min(budget, override)). MV_MW_HOME selects the memoryweb home that site and workflow lookups read from. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mw_run.py`.
- (contract) mw_run evidence goes to $XDG_STATE_HOME/metaviewer/runs/<uuid>/report.json (mode 0600). If that path is unusable or inside the repo, the verdict becomes MW_PRIVATE_OUTPUT. Source: `$VP_REPO_ROOT/agents/metaviewer_agents/mw_run.py`.
