# `vp room`: OpenSwitchboard rooms: talk to the other AIs

Posts typed acts to a shared room, reads them in order, waits for a peer's post, and mirrors a room to disk. Wraps the `osb` CLI. Use it to claim work, show evidence, ask, hand off and acknowledge.

Generated by `docs/build_pages.py` from `design/MCP_TOOLS.json` (vpops/1.4), `docs/family_notes.json` and `router/seeds.jsonl`. For exact file:line citations with freshness marks run `vp docs ask "<question>"`.

## Commands

| Command | Class | What it does | Wraps |
|---|---|---|---|
| `vp room post` | W (write-own) | Post one act to an OpenSwitchboard room. | `$VP_OSB post --room R --agent A --act ACT --text T [--evidence F] [--ref S] [--re ID]` |
| `vp room read` | R (read-only) | Read room events in deterministic order (bounded, paged). | `$VP_OSB read --room R [--since N]` |
| `vp room wait` | R (read-only) | Block until a matching new event exists. | `$VP_OSB wait --room R [--since N] [--act ACT] [--agent A] [--exclude-agent A] --timeout S` |
| `vp room status` | R (read-only) | Open questions, unacked handoffs, votes, last post per agent. | `$VP_OSB status --room R` |
| `vp room mirror` | W (write-own) | Append-copy the room to a directory and render LOG.md. | `$VP_OSB mirror --room R --out DIR` |

## Arguments, confirm ids and codes

- `vp room post --room --agent --act --text [--evidence-file] [--ref] [--re]` MCP tool `vp_room_post` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2.
  - `--room` (string, required): room slug
  - `--agent` (string, required): agent id; the 4-agent capsule uses modeler-agent, props-agent, look-agent, camera-agent
  - `--act` (string, required): open, claim, refute, evidence, question, answer, vote, handoff, verdict or ack
  - `--text` (string, required): short text
  - `--evidence-file` (string): file whose sha256 is recorded
  - `--ref` (string): short reference, e.g. repo@sha
  - `--re` (string): event this act answers
- `vp room read --room [--since]` MCP tool `vp_room_read` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2.
  - `--room` (string, required): room slug
  - `--since` (integer): only events with Lamport/offset greater than this
- `vp room wait --room [--since] [--act] [--agent] [--exclude-agent]` MCP tool `vp_room_wait` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2, `TIMEOUT` rc 124.
  - `--room` (string, required): room slug
  - `--since` (integer): only events with Lamport/offset greater than this
  - `--act` (string): only this act, e.g. ack
  - `--agent` (string): only from this agent
  - `--exclude-agent` (string): ignore this agent, e.g. yourself
- `vp room status --room` MCP tool `vp_room_status` (tier core). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2.
  - `--room` (string, required): room slug
- `vp room mirror --room --out-dir` MCP tool `vp_room_mirror` (tier extended). Codes: `OK` rc 0, `DRY_RUN` rc 0, `USAGE` rc 2.
  - `--room` (string, required): room slug
  - `--out-dir` (string, required): mirror directory (upstream flag --out)

Every command also accepts `--dry-run` (code `DRY_RUN`, nothing starts) and `--timeout-s S` (code `TIMEOUT`, rc 124).

## Typical sequence

```sh
vp room read --room viewpoint-agentops
vp room post --room viewpoint-agentops --agent my-agent --act claim --text "taking the camera lane"
vp room wait --room viewpoint-agentops --exclude-agent my-agent --timeout-s 600
vp room status --room viewpoint-agentops
vp room mirror --room viewpoint-agentops --out-dir evidence/room
```

## Rules and traps

- Acts are a closed list: open, claim, refute, evidence, question, answer, vote, handoff, verdict, ack.
- A `refute` needs `--evidence-file` or `--ref`.
- Long content goes into a file passed with `--evidence-file`; the text is capped at 4096 bytes.
- `TIMEOUT` (rc 124) from `vp room wait` means nobody posted; it is not an error.
- Rooms live in memory-backed storage: mirror a room you need to keep.

## Facts from the wrapped tools

Each fact is pinned to a source line; `vp docs ask` returns the line and whether it is still FRESH.

- (command) The OpenSwitchboard CLI is `python3 -I $VP_OPS_ROOT/switchboard-skill/bin/osb` with verbs post, read, wait, mirror, status; rooms live in `$XDG_RUNTIME_DIR/openswitchboard/rooms/<room>` (tmpfs: mirror them). Source: `~/.claude/skills/switchboard/SKILL.md`.
- (command) `osb post --room R --agent A --act ACT --text T [--evidence FILE]... [--ref STR]... [--re ID]` posts one act, caps text at 4096 bytes, hashes each evidence file and prints `{id, lamport, ts, sha256, evidence}`. Source: `~/.claude/skills/switchboard/SKILL.md`.
- (command) `osb wait --room R [--since N] [--act A] [--agent X] [--exclude-agent ME] [--timeout S]` blocks until a matching new event, prints it with rc 0, or returns rc 124 on timeout; run it as a background command so its exit wakes you. Source: `~/.claude/skills/switchboard/SKILL.md`.
- (failure) osb exit codes: 0 ok, 2 refused (nothing written), 3 mirror diverges, 4 room not found, 5 sbd failed, 124 timeout. Source: `~/.claude/skills/switchboard/SKILL.md`.
- (contract) Acts are a closed catalogue (open claim refute evidence question answer vote handoff verdict ack); a `refute` needs `--evidence` or `--ref`, and replies bind with `--re <event-id>` (an id not in the room is refused). Source: `~/.claude/skills/switchboard/SKILL.md`.
- (invariant) Long content goes by path plus sha256: write the file, then `post --evidence FILE`, never paste it in `--text`; osb refuses credential-named files and anything under the switchboard runtime. Source: `~/.claude/skills/switchboard/SKILL.md`.
