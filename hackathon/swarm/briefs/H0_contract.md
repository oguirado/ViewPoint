3. **THINK / ENQUEUE / TURN / RETURN Cycle (NON-INTERACTIVE Turns)**
   - **CAPTURE**: Broker publishes immutable `frame_<N>.png` + `frame_<N>.json`.
   - **THINK**: Agents plan in parallel against frozen `frame_<N>`. Agent thinking time is outside turn budgets (`TURN_TIMEOUT` covers broker-dispatched jobs and GUI acts, never agent thinking).
   - **ENQUEUE**: Agent writes `/dev/shm/vqa-cu/swarm/intents/<agent_id>/<event_id>.json`. Bounded per-agent FIFO of 8 pending intents; a 9th pending intent is refused with `QUEUE_FULL` without overwriting. Duplicate `event_id` is refused with `DUPLICATE_EVENT`.
   - **TURN (NON-INTERACTIVE)**: Round-robin over the agent ring (`modeler-agent`, `props-agent`, `look-agent`, `camera-agent`), with priority HI `control` events (`director-agent`) inserted only at turn boundaries. Turns are **non-interactive**: when an agent's turn opens (`head_frame = H`), there is no interactive wait/confirm loop with the agent; if the agent has no queued intent, the broker emits `PASS` (`tick` does not advance) and moves immediately to the next agent.
     - **Script intent (`lane: "script"`)**: Broker checks `lease_epoch` and verifies every entry of `write_set` matches the agent's active claim prefixes (disjoint claims mean script intents do not require `based_on_frame == H` rebase). Outside claim -> `CLAIM_REFUSED`. Valid -> dispatch `<nonce>__<tick>__<event_id>.py` to `SWARM_INBOX`, wait up to `120000 ms` (`120 s` cap) for outbox JSON. `OK` -> `STATE_VERIFIED` (`scene_epoch + 1`); `ERROR` -> `JOB_ERROR`; timeout -> `TURN_TIMEOUT` / missing reply -> `OUTCOME_UNCERTAIN` (queue enters `RECONCILE`, never auto-repeats).
     - **GUI intent (`lane: "gui"`)**: Permitted ONLY on `camera-agent`'s turn (`NO_LEASE` / `CLAIM_REFUSED` for any other agent). Allowed keys in queued `keys` list (`1..8` acts, `max_acts <= 8`): `KP_1`, `KP_3`, `KP_7`, `KP_4`, `KP_Add`, `Home`. `STALE_FRAME` applies to GUI intents: if `based_on_frame < H` and `rebased` is not permitted/valid, refuse with `STALE_FRAME` (`drops + 1`; 3 drops -> park event and emit `refute`; if `based_on_frame` evicted from frame ring -> `FRAME_EVICTED`). When admitted: broker first runs one viewport hover `vision act --job vpswarm --xy 800,500 --expect-change none` (or viewport focus), then executes each queued key via `vision act --job vpswarm --key <KEY> --expect-change 0,80,1580,900` under a `60000 ms` (`60 s`) GUI turn cap. `rc == 0` -> `VERIFIED` (or `VERIFIED_WITH_SPILL` if changes fall outside `footprint`); `rc == 3` -> `NO_VISIBLE_CHANGE` (never repeat blindly); uncertain/timeout -> `INPUT_UNCERTAIN` (enter `RECONCILE`, never auto-repeat). Admitted viewport change increments `view_epoch`.
   - **CLOSE & RETURN**: Broker captures `frame_<N+1>`, writes `close` + `cursor` (`phase: "result"`) records to `events.jsonl`, advances `tick` (`action_seq + 1` on dispatched closed events), and returns the agent to the ring tail. Two consecutive `TURN_TIMEOUT`s on an agent park that agent.
