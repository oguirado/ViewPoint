## 1. Provenance & Scope

This contract specifies the single-capsule multi-agent architecture for **ViewPoint Swarm**:
- **Planning Agents (4 headless)**: `modeler-agent`, `props-agent`, `look-agent`, `camera-agent`.
- **Orchestrator (1)**: `director-agent` (issues priority HI `control` records only).
- **Shared Execution Target**: ONE Blender 4.0.2 instance (`vision` job `vpswarm`) managed by a single turn-queue / actor broker.

The capsule runs as a **discrete-event simulation** with one total order recorded by the broker:
- State changes occur exclusively at ordered broker-admitted events; nothing mutates scene or viewport state between events.
- **Parallelism** lives in agent reasoning, frame inspection (`frames/`), script authoring, and intent enqueueing.
- **Execution is strictly exclusive**: the Blender bridge runs script jobs on Blender's main thread (`bpy.app.timers`), and the broker runs GUI acts sequentially via `vision`. Script jobs and GUI acts never overlap.

### 2.1 Bridge Inbox / Outbox Protocol
1. **Job filename format**: `<nonce>__<seq>__<event_id>.py` (written atomically via `.tmp` + `os.replace()`). Here `<nonce>` equals `SWARM_BRIDGE_NONCE` (lowercase hex) and `<seq>` is the broker-assigned integer sequence (equal to the dispatch `tick`).

## 3. THINK / ENQUEUE / TURN / RETURN Cycle (Non-Interactive Turns)

### 3.1 Phase Overview
1. **CAPTURE**: Broker captures the capsule display via `vision look --job vpswarm`, computes `changed_regions` against the prior frame, and atomically publishes immutable `frame_<N>.png`, `frame_<N>.json`, and `latest.json`.
2. **THINK**: Agents read `frames/` in parallel and plan against frozen `frame_<N>`. Agent thinking time is completely outside turn budgets (`TURN_TIMEOUT` covers broker-dispatched jobs and GUI acts, never agent thinking).
3. **ENQUEUE**: Agent writes `/dev/shm/vqa-cu/swarm/intents/<agent_id>/<event_id>.json` atomically via `.tmp` + rename and optionally emits a `cursor` intent hint.
   - **Bounded per-agent FIFO**: max `8` pending intents per agent. A 9th pending intent is refused with `QUEUE_FULL` without overwriting any queued intent.
   - **Idempotency**: An `event_id` already seen (queued, active, or closed) is refused with `DUPLICATE_EVENT`.
4. **TURN (NON-INTERACTIVE)**:
   - **Ring order**: Deterministic round-robin over `["modeler-agent", "props-agent", "look-agent", "camera-agent"]`.
   - **Priority HI `control`**: `control` events from `director-agent` are inserted ONLY at turn boundaries (never mid-act or mid-job).
   - **Non-interactive rule**: When an agent's turn opens (`head_frame = H`), there is NO interactive wait/confirm loop with the agent. If the agent's FIFO is empty, the broker emits `PASS` (`tick` does not advance) and advances immediately to the next agent in the ring.
   - **Turn dispatch by lane**:
     - **Script intent (`lane: "script"`)**:
       1. Broker checks lease validity (`NO_LEASE` if missing, `LEASE_EXPIRED` if `lease_epoch` is stale or `now_ms > expires_ts_ms`) and verifies every entry in `write_set` starts with one of the agent's active `write_prefixes`. Any mismatch is refused with `CLAIM_REFUSED`.
       2. Because claims are disjoint, script intents do NOT require `based_on_frame == H` rebase.
       3. Broker writes `<nonce>__<seq>__<event_id>.py` (where `<seq>` = dispatch `tick`) atomically to `SWARM_INBOX` and waits up to `120000 ms` (`120 s` cap) for `<nonce>__<seq>__<event_id>.json` in `SWARM_OUTBOX`.
       4. Receipt `status == "OK"` -> `STATE_VERIFIED` (`scene_epoch` increments by `1`).
       5. Receipt `status == "ERROR"` -> `JOB_ERROR` (unchanged state is not proven; agent must re-observe).
       6. Timeout (`> 120000 ms`) -> `TURN_TIMEOUT`; missing/corrupt outbox reply -> `OUTCOME_UNCERTAIN` (queue enters `RECONCILE`, never auto-repeats).
     - **GUI intent (`lane: "gui"`)**:
       1. Permitted ONLY on `camera-agent`'s turn (any other agent receives `NO_LEASE` if out of turn / unleased, or `CLAIM_REFUSED` because `allow_gui` is `false`).
       2. Allowed `keys` (`1..8` acts, `max_acts <= 8`): `KP_1`, `KP_3`, `KP_7`, `KP_4`, `KP_Add`, `Home`. Any disallowed key or missing `footprint` (when required for region attribution) is refused (`CLAIM_REFUSED` / `FOOTPRINT_MISSING`).
       3. **Frame freshness check**: If `based_on_frame` has been evicted from the broker's frame ring -> refuse with `FRAME_EVICTED`. If `based_on_frame < H` and `rebased` is not permitted/valid -> refuse with `STALE_FRAME`, increment `drops + 1`, and return event to the agent's tail. At `drops == 3`, park the event and emit `refute`.
       4. **Admitted GUI execution** (under `60000 ms` / `60 s` GUI turn cap):
          - Broker first runs one viewport focus/hover: `python3 -I ~/Documentos/vis-skill/vision act --job vpswarm --xy 800,500 --expect-change none`.
          - Broker then executes each queued key sequentially: `python3 -I ~/Documentos/vis-skill/vision act --job vpswarm --key <KEY> --expect-change 0,80,1580,900`.
       5. **GUI outcome classification**:
          - `rc == 0` -> `VERIFIED` (or `VERIFIED_WITH_SPILL` if `changed_regions` extend outside `footprint`). Admitted viewport change increments `view_epoch` by `1`.
          - `rc == 3` -> `NO_VISIBLE_CHANGE` (never repeat blindly).
          - Timeout (`> 60000 ms`) or ambiguous `vision` exit -> `INPUT_UNCERTAIN` (queue enters `RECONCILE`, never auto-repeats).
5. **CLOSE & RETURN**:
   - Broker captures `frame_<N+1>`, writes `close` and `cursor` (`phase: "result"`) records to `events.jsonl`, advances `tick` (`action_seq + 1` on dispatched closed events; `PASS` and admission refusals do not advance `tick`), and returns the agent to the tail of the ring.
   - **Consecutive timeout rule**: Two consecutive `TURN_TIMEOUT` outcomes on an agent automatically park that agent (`control` `op: "park"`).

### 3.2 State Machine

```text
EVENT:
  DRAFT --enqueue--> QUEUED --turn arrives--> HEAD
    ^                  ^                        |
    |                  |               ADMIT (broker state only)
    |                  +--STALE_FRAME / TIMEOUT-+--- other refusals ---> DROPPED (receipt)
    |                     (tail, drops+1; 3 => PARKED)
    |                                           | admitted
    |                                           v
    |                                       DISPATCHED --timeout/no reply--> UNCERTAIN
    |                                           | outbox / verify frame         |
    |                                           v                            RECONCILE
    +------- agent returns to ring tail ---- CLOSED(verdict) <--resolved--------+
                                                                unresolved --> STOP

QUEUE:
  IDLE --> TURN_OPEN (empty FIFO: PASS -> next agent) --> WINDOW_OPEN --> IDLE
                                                              |
                                                              v (uncertain)
                                                          RECONCILE --> IDLE | FROZEN (stop)
  FROZEN --control(resume), epochs+1--> IDLE
```

### 3.3 Watchdog & Crash Recovery
- **Dead agent**: If an agent's recorded PID exits before dispatch, its queued events are dropped.
- **Hung Blender main thread**: Watchdog kills only the recorded Blender PID and restores the last checkpoint `.blend` (`control` `op: "checkpoint"`). Surface incarnation changes invalidate all queued frames as `STALE_FRAME` / `FRAME_EVICTED`.

## 4. Claim / Lease Records (Epoch & TTL)

The broker maintains an authoritative lease table and logs every grant/renewal to `events.jsonl` as a `rec: "claim"` record:

```json
{
  "v": 1,
  "rec": "claim",
  "agent_id": "modeler-agent",
  "lease_id": "lease-modeler-0001",
  "lease_epoch": 1,
  "ttl_ms": 300000,
  "issued_ts_ms": 1731580000000,
  "expires_ts_ms": 1731580300000,
  "allow_gui": false,
  "write_prefixes": ["col:CHAR_", "obj:CHAR_"]
}
```

### 4.1 Default Disjoint Claims

| `agent_id` | `write_prefixes` | `allow_gui` |
|---|---|---|
| `modeler-agent` | `["col:CHAR_", "obj:CHAR_"]` | `false` |
| `props-agent` | `["col:PROPS_", "obj:PROP_"]` | `false` |
| `look-agent` | `["mat:", "light:", "world:"]` | `false` |
| `camera-agent` | `["cam:", "render:"]` | `true` |

### 4.2 Lease Enforcement Rules
- **Prefix check**: For `lane: "script"`, `write_set` MUST be non-empty, and every element `w` in `write_set` MUST satisfy `any(w.startswith(p) for p in claim.write_prefixes)`. Otherwise -> `CLAIM_REFUSED`.
- **GUI check**: For `lane: "gui"`, `claim.allow_gui` MUST be `true` AND the agent MUST hold the active head turn (`camera-agent`). Otherwise -> `NO_LEASE` (no active turn/lease) or `CLAIM_REFUSED` (`allow_gui: false`).
- **Epoch & TTL check**: Any intent or late action carrying `lease_epoch != active_claim.lease_epoch` or arriving after `expires_ts_ms` is refused with `LEASE_EXPIRED`. Missing lease entry -> `NO_LEASE`.

## 6. Complete Enumeration of Verdict & Refusal Codes

| Code | Category | Trigger Condition | Broker Action & Side Effects |
|---|---|---|---|
| `VERIFIED` | Outcome (GUI) | `vision act` exits `rc == 0` and all `changed_regions` lie inside `footprint` | `tick + 1`, `view_epoch + 1`, capture `frame_<N+1>` |
| `VERIFIED_WITH_SPILL` | Outcome (GUI) | `vision act` exits `rc == 0` and `changed_regions` also appear outside `footprint` | `tick + 1`, `view_epoch + 1`, populate `spill_regions`, capture `frame_<N+1>` |
| `NO_VISIBLE_CHANGE` | Outcome (GUI) | `vision act` exits `rc == 3` (zero pixel diff) | `tick + 1`, `view_epoch` unchanged, never repeat blindly |
| `INPUT_UNCERTAIN` | Outcome (GUI) | GUI act times out (`> 60000 ms`) or `vision` returns an uncertain/error exit | `tick + 1`, queue enters `RECONCILE`, never auto-repeat |
| `STATE_VERIFIED` | Outcome (Script) | Bridge outbox receipt has `status == "OK"` | `tick + 1`, `scene_epoch + 1`, capture `frame_<N+1>` |
| `JOB_ERROR` | Outcome (Script) | Bridge outbox receipt has `status == "ERROR"` | `tick + 1`, `scene_epoch` unchanged, capture `frame_<N+1>`, agent must re-observe |
| `OUTCOME_UNCERTAIN` | Outcome (Script) | Bridge outbox receipt is missing, malformed, or unconfirmed after dispatch | `tick + 1`, queue enters `RECONCILE`, never auto-repeat |
| `STALE_FRAME` | Refusal (GUI) | `based_on_frame < H` (and not validly rebased) at turn head | No dispatch, `drops + 1`, requeue at agent tail (at `drops == 3`: park + `refute`) |
| `FRAME_EVICTED` | Refusal (GUI) | `based_on_frame` has been evicted from the broker's frame ring | No dispatch, event dropped; agent must full re-observe `latest.json` |
| `NO_LEASE` | Refusal (Auth) | Agent lacks an active lease record, or submits a GUI act out of turn | No dispatch, `tick` unchanged |
| `LEASE_EXPIRED` | Refusal (Auth) | Intent/action carries stale `lease_epoch` or arrives past `expires_ts_ms` | No dispatch, `tick` unchanged |
| `ACTUATOR_BUSY` | Refusal (Lock) | Dispatch attempted while Blender main thread or `vision` actuator is occupied | No dispatch, `tick` unchanged (invariant guard) |
| `FOOTPRINT_MISSING` | Refusal (Validation) | GUI intent omits `footprint` (`null` or invalid `[x,y,w,h]`) | No dispatch, event dropped, `tick` unchanged |
| `TURN_TIMEOUT` | Timeout | Dispatched script exceeds `120000 ms` or GUI turn exceeds `60000 ms` | `turn_epoch + 1`, advance ring; 2 consecutive `TURN_TIMEOUT`s park agent |
| `QUEUE_FULL` | Refusal (Enqueue) | Agent already has `8` pending intents in its FIFO | Reject 9th intent without overwriting |
| `DUPLICATE_EVENT` | Refusal (Enqueue) | `event_id` was already enqueued/processed | Reject duplicate without re-execution |
| `CLAIM_REFUSED` | Refusal (Auth) | `write_set` falls outside `write_prefixes`, `allow_gui` is `false` for GUI lane, or disallowed key in `keys` | No dispatch, event dropped, `tick` unchanged |
| `PASS` | Turn Control | Head agent's FIFO is empty when its turn opens | No dispatch, `tick` unchanged, immediately advance to next agent |

## 8. Explicit `AUSENTE` Registry

The following capabilities do not exist in the current substrate and MUST NOT be invented or assumed by any downstream unit:

1. **Scene-digest helper for semantic 3D mesh diffing**: `AUSENTE` — script-lane oracle relies exclusively on bridge receipt `status == "OK"`, `error == null`, and disjoint `write_prefixes` claim enforcement.
2. **`osb` cross-process read-ordering guarantee**: `AUSENTE` — `~/Documentos/viewpoint-hackathon/swarm/run/events.jsonl` (`SWARM_EVENTS_LOG`) is the sole total-order authority; `osb` is a read-only projection.
3. **`bpy` 2D screen-space bounding-box cursor projection**: `AUSENTE` — MVP script events use the deterministic per-agent viewport anchor slots specified in Section 5.2 (`cursor`).
4. **Mouse drag in `vision`**: `AUSENTE` (unsupported) — viewport navigation MUST use the allowed numpad keys (`KP_1`, `KP_3`, `KP_7`, `KP_4`, `KP_Add`, `Home`) only.
