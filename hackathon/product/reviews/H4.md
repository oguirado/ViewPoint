## Findings, most severe first

### MAJOR

**M1. The integrated `--finalize` path hides a failed `close_task`, so `MISSING_CLOSE_TASK` cannot fire.**
- `projector.py:903-908` adds the agent to `state.closed_agents` without checking what `sink.close_task` returned. `TaskLightMcpSink.call_tool` only logs a warning when the store refuses the call with `isError` (`projector.py:485-486`). Store refusals include `room_full` and `bad_agent` (`store.py:433-434`, `mcp.py:228-229`).
- `Projector.finalize` (`projector.py:961-975`) then passes that state to the reconciler. The reconciler merges `state.closed_agents` into `cw_closed_agents` (`reconciler.py:209-216`), so the negative control at `reconciler.py:222-228` reads the projector's own claim instead of the TaskLight room.
- Probe P2 [MEASURED]: a sink whose `close_task` returns `{"isError": true}` produces `clean: True` with `agents_closed: ['props-agent']`.
- Result: the reconciler's audit agrees with whatever the projector already believes. Only the standalone reconciler CLI run without `--state-file` reads the room independently.
- Expected behaviour, in prose: only mark an agent closed after a non-error result. The reconciler should treat the TaskLight room's `act == "close"` events as the only evidence of `close_task`, and use the projector state at most as a cross-check that reports disagreement.

**M2. `control op=stop` closes every TaskLight task, and nothing reopens them after `resume`.**
- `projector.py:889-890` calls `finalize_open_tasks` on every `stop`, with the outcome `"Completed capsule tasks for …"` (`projector.py:900`).
- Contract §3.2 says `FROZEN --control(resume)--> IDLE`, and §7.2 says `close_task` belongs to "Final completion". A stop is a pause, not completion.
- After a `resume`, the agent is still in `planned_agents`, so the check at `projector.py:720` issues no new `post_plan`. Later `post_step`/`post_status` calls are written into a task that is already closed, and the reconciler still reports CLEAN.
- Probe P1 [MEASURED]: the TaskLight calls were `post_plan, post_step 0, close_task, post_step 1`, and the reconciler returned `clean: True, anomalies: []`.
- Expected behaviour, in prose: on `stop`, call `post_status` with a paused or blocked state, and keep `close_task` for `--finalize` or a terminal stop. Alternatively, on `resume`, clear `closed_agents` and send a new `post_plan`.

### MINOR

**m1. The step index saturates at 11, which breaks §7.2's "exactly one microtask per `close` receipt".**
- `projector.py:99-101` clamps the index to `min(idx, 11)`. Every close after the 12th overwrites step 11.
- Refusals also consume steps (`projector.py:838-848`). A single GUI event that is requeued three times as `STALE_FRAME` uses three slots.
- Probe P4 [MEASURED]: 14 closes produced indices `[0..11, 11, 11]`.
- Neither the README (`README.md:76-77`, "index 0..11") nor the tests mention this. The 12-step limit comes from `store.py:75`, so the fix is to document the collapse or roll over to a new `post_plan`, not to raise the limit.

**m2. The `refute` emitted for `control park` never carries an event id; its ref is always the literal `"park"`.**
- `projector.py:872` falls back through `event_id` and then `agent_id` to `"park"`. H1's park records contain neither field (`swarm/broker/broker.py:796-803`, `959-964`); the target only appears inside `reason` (for example `parked_after_3_stale_drops:<event_id>`).
- Probe P5 [MEASURED]: the result was `('refute', 'park')`.
- `osb` accepts it, so there is no rc 2, but §7.1's "`--ref <event_id>`" is not met.
- This is partly a contract gap: the §5.2 `control` schema has no target field.
- The impact is limited because the `STALE_FRAME` or `TURN_TIMEOUT` `close` record just before the park already emits a correctly referenced `refute`. The park refute adds a duplicate with a meaningless ref.
- The reconciler's park check at `reconciler.py:162-168` uses the same fallback, so it can never fire.

**m3. `refute`, `evidence` and `verdict` text is built from broker `reason` without sanitising it, so `osb` can still exit with rc 2.**
- `projector.py:822`, `862` and `876` put `reason` into `--text` unchanged.
- `osb` refuses any control character other than `\n`/`\t`, and any text over 4096 bytes (`osb:143-153`). H1 copies the bridge's `error` into `reason`, capped at 300 characters but not cleaned (`swarm/broker/broker.py:845`).
- [MEASURED]: `osb post --act refute --ref x` with a `\r` in the text printed `refused: text has control character U+000D` and exited `rc=2`, writing nothing.
- `OsbSink` only logs a warning (`projector.py:389-395`) and the offset still advances, so that refute is lost permanently.
- Strip or escape control characters and cap the text length before calling `osb`.

**m4. A refusal `close` with a null or empty `event_id` is dropped silently.**
- `projector.py:783-784` returns early whenever `event_id` is falsy, before checking the verdict. The fallback ref at `projector.py:821` is therefore unreachable.
- Probe P5 [MEASURED]: a `NO_LEASE` close with `event_id: null` produced no `refute` and no `post_step`.
- `reconciler.py:136` has the same early skip, which makes its `MISSING_REF_ON_REFUSAL` check at `reconciler.py:143-151` vacuous: `ev_id` is always truthy at that point.
- Only `PASS` should take the early exit.

**m5. A partial trailing line is consumed and lost for good.**
- `run_once` reads with `readline()`, JSON-decodes whatever it got, logs a decode failure, and still advances `offset_bytes` (`projector.py:921-935`). The rest of the record then fails to decode on the next poll.
- Probe P3 [MEASURED]: a line written in two halves produced no `claim` at all, with the offset at 135 out of 135.
- H1 writes each line with a single `write` plus `flush` (`swarm/broker/broker.py:316-321`), so the race is narrow. In `--follow` mode, though, the loss is permanent and silent.
- Only consume lines that end in `\n`.

**m6. The reconciler tracks reconciliation with one global flag, and `resume` counts as reconciliation.**
- `reconciler.py:100`, `156` and `169-174` use a single boolean.
- If event A is uncertain, then a `reconcile` arrives, then event B is uncertain, both A and B are flagged. Probe P6 [MEASURED]: `['modeler-agent-1', 'props-agent-1']`.
- If an uncertain event is followed only by a `resume` from `operator`, it counts as reconciled. Probe P7 [MEASURED]: `[]`.
- Track reconciliation per event: an event is cleared by a `reconcile` that comes after it. Decide explicitly whether `resume` should clear it.

**m7. Some outcome verdicts are classified as refusals.**
- `REFUSAL_VERDICTS` (`projector.py:40-54`) contains `JOB_ERROR`, `INPUT_UNCERTAIN`, `OUTCOME_UNCERTAIN` and `TURN_TIMEOUT`. Contract §6 lists these as Outcome or Timeout, not Refusal. `NO_VISIBLE_CHANGE`, which is also an unverified outcome, goes to `evidence`.
- `projector.py:816` (`… or verdict`) also turns any unknown verdict into a `refute`, without logging.
- Mapping a dispatched failure to `refute` is defensible, but it should be documented as a decision against §6's categories. Unknown verdicts should be logged.

**m8. The projector re-saves and fsyncs its state on every idle poll.**
- `run_once` calls `state.save` on every call, including when it processed 0 lines (`projector.py:937-938`). `run_follow` polls every 0.1 s (`projector.py:942-953`), so an idle daemon does about 10 fsyncs per second.
- `--follow` with no `max_idle_s` only stops on `KeyboardInterrupt` (`projector.py:955`). A SIGTERM skips the final save in `finally` and skips `--finalize`.

### NIT

- **n1.** `control stop`/`resume` is always posted as agent `director-agent` (`projector.py:866`). The record's `by` is read at `projector.py:859` but never used. Probe P8 [MEASURED]: a `stop` with `by: operator` was posted as `director-agent`.
- **n2.** PASS turns (`swarm/broker/broker.py:1142-1162`, `hold_ms: 0`) still emit `handoff`, `ack` and a TaskLight `post_status` saying "Acting on turn #N" (`projector.py:744-773`), while the matching PASS `close` is skipped. The status text is wrong for a PASS.
- **n3.** `reconciler.py:266` and `295` annotate with `Sequence`, which is never imported (`reconciler.py:20`). It only works because of `from __future__ import annotations`.
- **n4.** `--once` (`projector.py:1020-1024`) is parsed but has no effect, because one-shot is already the default.
- **n5.** `TaskLightMcpSink` never drains the child's stderr pipe (`projector.py:425`), and `_read_raw` (`projector.py:462`) blocks with no timeout. A hung or chatty `bridge.room.mcp` stalls the projector indefinitely. Low risk: the server writes nothing to stderr normally (`mcp.py:113-116`).
- **n6.** `OsbSink._env` passes through the full `os.environ` (`projector.py:311-315`). If the projector is ever started from a swarm lane with `OSB_LANE=1`, `osb`'s lane policy refuses `ack`, `refute` and `verdict` and caps the lane at 5 acts (`osb:605-606`, `653-655`). Scrubbing `OSB_LANE` would remove that dependency.
- **n7.** The README overstates two guarantees. It claims the offset "eliminat[es] duplicate posts" (`README.md:101`), but posts are at-least-once: side effects happen before `state.save`, and a sink exception mid-file replays them. It also presents `MISSING_REF_ON_REFUSAL` as a live check (`README.md:109`), but by construction it cannot fire (m4).
- **n8.** The room auto-open path (`projector.py:339-346`) depends on `sbd send` creating a room that does not exist yet. That is not verified here: AUSENTE — no inventar. I did not exercise it against the live daemon, to avoid writing to a real room.
