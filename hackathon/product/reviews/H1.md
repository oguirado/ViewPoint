## Findings (ranked)

### BLOCKER

**B1. `event_id` path traversal: the broker overwrites, then deletes, any host `.py` file.**
- `swarm/broker/broker.py:555` takes `event_id` straight from the intent file and never validates it.
- `swarm/broker/broker.py:735-741` puts it into the job filename.
- `atomic_write_text` at `swarm/broker/broker.py:100-104` calls `mkdir(parents=True)` on the parent. That materialises a `<nonce>__<seq>__..` directory inside the inbox, so the `..` segments that follow walk out of `SWARM_INBOX`.
- On timeout, `swarm/broker/broker.py:777-778` unlinks the same escaped path.

**Proof**: an intent with `event_id` `../../../victim` made the broker replace a pre-existing `victim.py` beside the test inbox with the agent's script, then delete it after the timeout. Probe output: `victim_during_dispatch: 'PWNED = 1'`, `victim_exists_after: False`.

**Why the bridge does not help**: its strict regex (`swarm/broker/bridge.py:35`) never sees the file. The broker is the trust boundary for intent data (CONTRACT §2: agents never write the inbox, and the broker writes it).

**Mitigation that exists**: H2's SDK rejects `/` in `event_id` (`swarm/agents/intent_cli.py:33`). An agent that writes the JSON directly bypasses that check.

**Required fix**: the broker must validate `event_id` against the bridge's character class (no `/`, not `.`/`..`). It must also confirm that the resolved job path's parent is `SWARM_INBOX`.

**B2. Poison-pill intents crash the broker, and keep crashing it after restart.**

In both the agent and director ingest loops, parsing happens before the file is archived. Archiving is at `swarm/broker/broker.py:553` and `swarm/broker/broker.py:529`. So an exception leaves the file in place and the next start crashes on it again.

| Input | Crash | Site | Probe |
|---|---|---|---|
| Valid JSON that is not an object (e.g. a list) | `AttributeError` | `swarm/broker/broker.py:548` | P1b |
| `created_ts_ms` set to `null` | `TypeError` | `swarm/broker/broker.py:548` | P1 |
| Director file with a non-numeric `created_ts_ms` | `ValueError` | `swarm/broker/broker.py:525` | P1c |
| `_drops` set to a non-numeric string | `ValueError` | `swarm/broker/broker.py:585` | P4b |
| Intent with no `event_id` | `KeyError` | `swarm/broker/broker.py:1164` (same pattern at `swarm/broker/broker.py:678` and `swarm/broker/broker.py:859`) | P2 |

Why a missing `event_id` crashes: ingest falls back to the filename stem (`swarm/broker/broker.py:555`) but never writes that fallback into the queued item (`swarm/broker/broker.py:584-588`). The later lookup by key then fails.

Probes P1, P1b and P1c all reported "file still in place = True" after the crash.

A related crash: if the outbox receipt is a JSON non-object, `receipt.get` at `swarm/broker/broker.py:805` runs before the `isinstance` guard on `swarm/broker/broker.py:807`.

### MAJOR

**M1. Agents can set fields in the intent file that bypass the stale-frame and park rules.**
- `swarm/broker/broker.py:585-586` copies `rebased` and `_drops` from untrusted intent JSON. `swarm/broker/broker.py:927-935` then trusts them.
- Probe P3: a camera intent with `based_on_frame` 0 against head frame 2, plus `"rebased": true`, got `VERIFIED_WITH_SPILL` (it should have been `STALE_FRAME`).
- Probe P4: `"_drops": -50` produced `STALE_FRAME` with drops -49, -48, … and was never parked.
- CONTRACT §3.1 step 4.3 (`swarm/CONTRACT.md:103`) requires `rebased` to be "permitted/valid", and §5.1 defines no `rebased` field. Rebase permission and the drop counter must be broker-owned state.

**M2. A script `TURN_TIMEOUT` leaves the actuator in an unknown state; there is no `RECONCILE` and no `ACTUATOR_BUSY` guard.**
- After a timeout, `swarm/broker/broker.py:776-803` unlinks the job and moves the ring on, still `IDLE` (probe P9: `queue_state` `IDLE`).
- The bridge's `exec` cannot be cancelled (`swarm/broker/bridge.py:162-165`). A job that is already running still mutates the scene later. Its effects never get a frame capture or a `scene_epoch` bump, and the next agent's job is dispatched while Blender's main thread is still busy.
- `ACTUATOR_BUSY` (`swarm/CONTRACT.md:262`) is never emitted anywhere in `swarm/broker/broker.py`.
- The unlink at `swarm/broker/broker.py:777-778` races the bridge. If it lands between `swarm/broker/bridge.py:154` and `swarm/broker/bridge.py:163`, the bridge writes an `ERROR` receipt for a job that never ran.
- `tick` is not advanced, so the next dispatch reuses the same `<seq>` (probe P9: tick 0 after dispatch).

**M3. A GUI timeout partway through a key sequence skips `RECONCILE`, even though keys were already delivered.**
- `swarm/broker/broker.py:1020-1049` maps `subprocess.TimeoutExpired` to `TURN_TIMEOUT` with no `RECONCILE`, no frame capture, and `view_epoch` unchanged.
- Probe P7: key 1 returned rc 0 and key 2 timed out. Result: `TURN_TIMEOUT`, `queue_state` `IDLE`, `view_epoch` 0, `head_frame` 0. The viewport had already changed.
- CONTRACT §3.1 step 4.5 (`swarm/CONTRACT.md:110`) says a timeout should give `INPUT_UNCERTAIN` and `RECONCILE`. §6 (`swarm/CONTRACT.md:264`) contradicts it. Escalate the contract conflict to H0. Whichever wording wins, half-delivered input has to be reconciled.

**M4. One rc 3 among the keys hides the view changes made by the others.**
- `swarm/broker/broker.py:1015-1016` sets `saw_no_change` whenever any key returns rc 3. `swarm/broker/broker.py:1068-1083` then closes the whole intent as `NO_VISIBLE_CHANGE` without bumping `view_epoch`.
- Probe P6: `KP_1` returned rc 0 with a region, `KP_3` returned rc 3. Verdict: `NO_VISIBLE_CHANGE`, `view_epoch` 0.
- From then on, published sidecars carry a `view_epoch` that understates real viewport changes.
- H2 classifies `NO_VISIBLE_CHANGE` as retryable (`swarm/agents/__init__.py:52`), which makes it worse: agents repeat key sequences whose earlier keys already took effect. That also conflicts with "never repeat blindly" (`swarm/CONTRACT.md:109`).

**M5. Leases are never renewed, so the swarm dies when the TTL runs out.**
- Leases are granted once at start-up (`swarm/broker/broker.py:323-342`) with a TTL of 3,600,000 ms (`swarm/broker/broker.py:56`).
- Nothing renews them. After expiry, `swarm/broker/broker.py:673-674` refuses every intent from every agent with `LEASE_EXPIRED`, permanently.
- CONTRACT §4 (`swarm/CONTRACT.md:148`) expects grant and renewal `claim` records. Using the contract's example `ttl_ms` of 300000 [CITED] would kill the run after 5 minutes.

**M6. The README's "offline dry-run" actually drives the live capsule.**
- `swarm/broker/README.md:20-21` runs `--vision-mode mock --drain-and-exit` with all defaults. Mock mode only replaces `vision`. The broker still:
  - rewrites the live `nonce.txt` (`swarm/broker/broker.py:281-283`), which invalidates every job from a running live broker;
  - consumes and archives live agent intents;
  - writes scripts into the live inbox, where the live Blender bridge runs them;
  - appends to the repo `swarm/run/events.jsonl`.
- `frames_dir` and `intents_dir` have no env override (`swarm/broker/broker.py:239-240`).
- No lock or pidfile enforces the single-writer broker assumption.

**M7. CONTRACT §3.3 (watchdog and crash recovery) is not implemented.**
- `checkpoint` is a no-op (`swarm/broker/broker.py:652-653`). Nothing tracks agent PIDs or drops a dead agent's events. There is no watchdog for a hung Blender main thread.
- If Blender hangs: every script hits `TURN_TIMEOUT`, then each agent is parked after 2 (`swarm/broker/broker.py:792-802`), and the capsule stalls until the director intervenes by hand.

**M8. In live mode, a failed `vision look` crashes the broker partway through a turn.**
- `capture_frame` raises `RuntimeError` (`swarm/broker/broker.py:395-401`) and nothing catches it.
- In the `STATE_VERIFIED` path, `scene_epoch` is incremented first (`swarm/broker/broker.py:831`) and the frame captured after (`swarm/broker/broker.py:832`). A transient failure therefore kills the run after the job ran but before its `close` record exists. On restart there is no record of the outcome.

### MINOR

**m1. `SWARM_BRIDGE_NONCE` means two different things.**
- The contract table (`swarm/CONTRACT.md:34`) lists `SWARM_BRIDGE_NONCE` with the nonce-file path as its default. `swarm/CONTRACT.md:40` uses it as the hex nonce value.
- H1 reads it as the value (`swarm/broker/broker.py:281`, `swarm/broker/bridge.py:59`) and adds an uncontracted `SWARM_NONCE_FILE` (`swarm/broker/broker.py:242`, `swarm/broker/bridge.py:53`).
- Probe P8: setting the variable per the table made the nonce a path. The job was written to an absolute location outside the inbox, giving `TURN_TIMEOUT`.
- The nonce is never checked to be hex. This needs an H0 erratum plus input validation.

**m2. The hover step treats every nonzero exit as uncertain input.**
- `swarm/broker/broker.py:993-994` maps any nonzero hover exit to `INPUT_UNCERTAIN`, which freezes the queue in `RECONCILE`.
- With `--expect-change none`, `vision` returns rc 3 on any unmasked visible change (the `vision` act verdict path). A hover highlight in Blender would therefore freeze the queue.

**m3. A `QUEUE_FULL` refusal uses up the event_id.**
- `swarm/broker/broker.py:570` records the id as seen before the capacity check at `swarm/broker/broker.py:572`.
- Probe P10: resubmitting the refused `e8` after the FIFO drained returned `DUPLICATE_EVENT`, although that event was never queued.

**m4. `DUPLICATE_EVENT` emits an `enqueue` record; `QUEUE_FULL` does not.**
- The `enqueue` record comes from `swarm/broker/broker.py:558`.
- H4 turns every `enqueue` into an osb `claim` and may `post_plan` (`swarm/projection/projector.py:702-735`), so the dashboards show a claim for a refused duplicate.

**m5. Control `op` and `by` are passed through unvalidated.**
- `swarm/broker/broker.py:628-630` and `swarm/broker/broker.py:655-663` do no validation. Probe P11 logged `op: "bogus"` and `by: "operator"`, both taken from a director file.
- `reconcile` sets `IDLE` even from `FROZEN` (`swarm/broker/broker.py:645-648`). That bypasses the `resume`-only exit from `FROZEN` in `swarm/CONTRACT.md:137`.

**m6. Park records do not say what was parked.**
- `swarm/broker/broker.py:794-802` and `swarm/broker/broker.py:957-965` name the agent or event only inside `reason`.
- H4 looks for `event_id` or `agent_id` (`swarm/projection/projector.py:871-873`), so its refute `--ref` falls back to the literal string `park`.
- The §5.2 control schema has no such fields. This needs a joint H1/H4 fix and a contract erratum.

**m7. Script-lane validation is incomplete.**
- `script_sha256: null` is accepted (`swarm/broker/broker.py:711-712`), although §5.1 requires it.
- `v`, `action_class`, `kind` and `max_acts` are never checked.
- The filename stem is not compared with `event_id`.
- `event_id` is not namespaced per agent, so any agent can burn another agent's future ids.

**m8. Idempotency is lost on restart.**
- Seen ids live only in memory (`swarm/broker/broker.py:298`), and the `processed/` archive is never consulted.

**m9. Refusals made at ingest carry an unrelated turn number.**
- `QUEUE_FULL` and `DUPLICATE_EVENT` closes are stamped with the current, unrelated `turn` (`swarm/broker/broker.py:559-581`).

**m10. A requeued `STALE_FRAME` still gets a `close` record (H2 interop).**
- `swarm/broker/broker.py:936-945` writes `close` for an event that has only been requeued.
- H2's `wait_for_close_event` (`swarm/agents/intent_cli.py:507-549`) returns on that first `close`, while the event is still queued.
- Because `camera-agent` is last in the ring, any `STATE_VERIFIED` earlier in the same sweep makes the camera's GUI intent stale. Expect agents to re-enqueue duplicate GUI intents.

**m11. The bridge leaves some inbox entries in place.**
- `swarm/broker/bridge.py:129-132` skips dotfiles, `*.tmp` files and directories instead of moving them to `SWARM_REJECTED`. Probe P12 left `stray.tmp` and `sub/` in the inbox.
- This is acceptable for in-flight temp files, but nothing ages them out.
- Captured stdout has no size cap (`swarm/broker/bridge.py:171-176`).

**m12. Old frames are never deleted.**
- When a frame leaves the ring (`swarm/broker/broker.py:428-431`), its `frame_<N>.png` stays in `/dev/shm`, so a long live run grows without bound.
