## Technical Requirements (`product/admission/`)
1. **`product/admission/SPEC.md`**:
   - Formal engineering specification extending ViewPoint's `observe -> propose -> wait-verify` admission pipeline with multi-actor identity (`actor_id`), epoch-versioned leases (`lease_id`, `lease_epoch`, `ttl_ms`, `allow_gui`, `write_prefixes`, `allowed_regions`), and region-scoped rebase (`STALE_REGION`, `STALE_VIEW`, `STALE_SCENE` vs strict `STALE_FRAME`).
   - Specify exact invariants: when `based_on_frame < current_frame`, automatic region-scoped rebase is sound IF AND ONLY IF `view_epoch` and `scene_epoch` match (otherwise `STALE_VIEW` / `STALE_SCENE`) AND the union of `changed_regions` across `(based_on_frame, current_frame]` has empty intersection (with safety margin) with the proposal's `target_region` and `footprint` (otherwise `STALE_REGION`). Foreign unattributed screen changes without region safety remain a typed refusal (`STALE_FRAME`).
2. **`product/admission/admission.py`**:
   - Clean, self-contained Python 3 stdlib reference implementation of the multi-actor `AdmissionController` supporting:
     - `issue_lease(...)`, `revoke_lease(...)`, `expire_leases(now_ms)`
     - `observe(actor_id, now_ms)` -> immutable `FrameObservation` (`frame_seq`, `view_epoch`, `scene_epoch`, `changed_regions`, `sha256`)
     - `propose(proposal, now_ms)` -> typed admission decision (`ADMITTED`, `ADMITTED_REBASED`, or typed refusal code)
     - `wait_verify(dispatch_token, post_frame_obs, executor_outcome, now_ms)` -> typed verification receipt
   - Support the complete verdict/refusal code set:
     `VERIFIED`, `VERIFIED_WITH_SPILL`, `NO_VISIBLE_CHANGE`, `INPUT_UNCERTAIN`, `STATE_VERIFIED`, `JOB_ERROR`, `OUTCOME_UNCERTAIN`, `STALE_FRAME`, `STALE_REGION`, `STALE_VIEW`, `STALE_SCENE`, `FRAME_EVICTED`, `NO_LEASE`, `LEASE_EXPIRED`, `ACTUATOR_BUSY`, `FOOTPRINT_MISSING`, `CLAIM_REFUSED`, `DUPLICATE_EVENT`, `TURN_TIMEOUT`.
3. **`product/admission/test_admission.py`**:
   - Real multi-peer concurrency test (`threading` / `multiprocessing` peers contending over `observe -> propose -> wait_verify` against one shared controller) proving zero double-actuation (`ACTUATOR_BUSY` / serialized window) and zero silent overwrite.
