# OpenSuperficies

Base: components/OpenSuperficies

## What this component is

OpenSuperficies is an autonomous Docker, Xpra and CDP substrate for isolated graphical surfaces. Each web is data and the engine is invariant. The standalone topology puts Xvfb, the window manager, the streaming layer and the browser inside one capsule; the boundary is a pair of loopback ports. The plan identity is `opensuperficies-v1` and the module is `opensuperficies.local/srf` on Go 1.26.0. Campaign notes live in `LOG-CAMPANA.md` and the canonical quickstart in `QUICKSTART.md`; the architecture map is `README.md`.

## Entry points and real commands

Build commands are declared in `Makefile`. `make build` runs `CGO_ENABLED=0 go build -trimpath -o bin ./cmd/...` and produces one binary per `cmd/` directory, including `cmd/srf-motor/main.go`, `cmd/srfd/main.go`, `cmd/srf-egress-proxy/main.go`, `cmd/srf-relay/main.go` and the Computer Use tools `cmd/srf-cu-wlcap`, `cmd/srf-cu-snap`, `cmd/srf-cu-exec` and `cmd/srf-cu-mcp`.

The surface operator is `scripts/docker-xpra-surface.sh`. Its verbs are `iniciar`, `verificar`, `detener`, `purgar`, `intervenir`, `blindar` and `estado`. A real session is `iniciar` with an instance name, an optional URL, width and height, followed by `verificar`, `estado`, `detener` and the raw `motor/cdp_runner.py` CDP state command. Its help text states that quarantine verification needs the host display baseline and that attach and consult live in `scripts/perplex-box.sh`. The script builds the image from `docker/Dockerfile.browser-arm64` when it is missing and publishes two loopback ports per instance: one for Xpra and one for CDP. The current allocator scans Xpra ports `10020..10099` and computes CDP as `xpra - 10000 + 9220`, yielding `9240..9319`; its source comment advertises a different CDP range. Both published ports bind to loopback; inside the container they map to port 10000 and port 9222. A custom stop therefore looks like `docker stop -t 15` rather than a bare kill.

`cmd/srfd` is the daemon door every managed capsule class passes through. Its `main` delegates to `manager.EjecutarDaemon` in `src/surfacebook/manager/uds.go`, which returns only after the teardown procedure has completed. Daemon teardown can return an error with live slots and retained durable custody; completion of the procedure is not proof that every capsule stopped. `cmd/srf-motor` drives the browser and CDP layers in `src/displaybook/`, `src/dockerapi/` and the CDP client. The CDP runner is `motor/cdp_runner.py`. `cmd/srf-egress-proxy` runs only the forward proxy and never creates networks or containers. `cmd/srf-relay` forwards between a listen address and a target CDP address; by default it listens on 9220 and targets 9222.

The cockpit app is `cockpit/main.go` built with the `cockpit` tag under Wails v2, embedding `cockpit/frontend/dist` and binding the Go `App` in `cockpit/app.go`. The frontend is a Svelte 5 runes app declared in `cockpit/frontend/package.json` with `vite`, `vitest run` and Playwright available. `cockpit/wails.json` configures the desktop build.

## Surface lifecycle

`scripts/docker-xpra-surface.sh iniciar <instance> [url] [width] [height]` is the auditable surface lifecycle. Defaults are URL for Perplexity, width 1280 and height 900. If the instance run file already exists it reports the surface as already started and exits without creating a second container. Otherwise it ensures the image, allocates one free port pair, creates a per-instance bridge network named after the instance, removes any previous container with the same name, and starts a detached container with read-only posture, dropped capabilities, no new privileges, memory 4g, memory-swap 4g, cpus 5, pids-limit 512 and shm-size 2gb. Profile, uploads and harvest directories are bind-mounted from staging; a 512m temporary file system is mounted for temporary use. Environment knobs include display number 100, geometry, openbox window manager, profile mode persistent or ephemeral, seed from persistent, read-only Xpra and the start URL. A small Python bridge then forwards the container network interface port 9222 to local CDP port 9222 with a maximum of 16 connections and a 60 second idle timeout, because Chromium hardcodes the local CDP port.

The standalone script currently resolves a fixed operator-checkout root; invoking a copy from another worktree does not rebind that root. Confirm path ownership before use. Here read-only means the Xpra viewer/input layer; this Docker invocation does not request a read-only container root filesystem.

`verificar` loads the instance run file and delegates to `docker/verify-quarantine.sh` with the container name and the Xpra port. The gate table in `README.md` describes fourteen quarantine doors plus display isolation, internal networking and image signing as separate gates B-01 to B-24. `intervenir` relaxes read-only to the operator, `blindar` restores it, `estado` prints the run file, container status, a truncated CDP version response, the viewer URL and the raw CDP runner state. `purgar` is the post-crash cleanup when no live container exists; `detener` is the normal teardown described below.

## Capture

Two capture paths exist. The exact framebuffer path is `src/ramcap`. `NewEngine` in `src/ramcap/engine.go` shares one session between capture and direct verification; the `Start` method on the `Capture` type takes slot, window id and TTL and returns an id, and `Stop`, `Provenance`, `Probe`, `SizeBytes` and `Reap` complete the lifecycle. `src/ramcap/README.md` states that production stores require the guarded run directory from `capture.DefaultGuard().CheckRunDir`, that readers run once with the caller deadline capped at two seconds, that recording history uses exclusive frame-named files, that the head file is replaced in place, and that only TTL, explicit reap and engine shutdown remove the session workspace. `src/ramcap/xwd.go` parses XWD frames, `src/ramcap/fbsource.go` is the framebuffer source, and `src/ramcap/store.go` manages the run workspace. The cockpit owns the bounded shim process and closes the engine before stopping it.

The Computer Use chunked path is `src/cubook/capture/livedriver.go`, `src/cubook/capture/analyzer.go` and the `cmd/srf-cu-wlcap`, `cmd/srf-cu-snap`, `cmd/srf-cu-exec` and `cmd/srf-cu-mcp` tools. The pacer is fixed-step at frame period 16666667 nanoseconds, sixty frames per chunk by default, default quota 2<<30 and maximum quota 8<<30. Late frames advance the render index and leave the gap visible; they are never back-filled. Frames live in a RAM workspace and at most two chunks are resident unless the run is explicitly kept. `src/cubook/capture/analyzer.go` runs per-chunk engine analysis through `vision/chunk_analyze.py`. The bench scenes in `bench/wl/scenes/` and the harness in `bench/cu/harness.py` and `bench/wl/driver.py` drive the same clocks. Live retention is false for 4K except for explicit handover mode.

## Cockpit

`cockpit/main.go` defines the fixed window 1280 by 1064 matching the frontend geometry authority in `cockpit/frontend/src/lib/geometria.ts` with its `cockpit/frontend/tests/geometria.test.ts` check. `cockpit/app.go` talks to `srfd` only over the single door described in the `cockpit/main.go` header. `cockpit/frontend/src/App.svelte` is the root view; its library covers capsules, cards, geometry, shell, telemetry, stack, terminal and workspace views. Twenty-three test files in `cockpit/frontend/tests/` cover geometry, shell, cards, cooperation, state mirror, telemetry truth, wiring, wall layout, workspace matrix and views 01 to 03, among others. `cockpit/frontend/tests/terminal.test.ts` is excluded from the monorepo frontend leg because it needs a live terminal fixture and Chromium; it runs separately when provided. The Go cockpit package has its own tests alongside `cockpit/app.go`, `cockpit/state.go`, `cockpit/ptyserver.go`, `cockpit/servicios.go`, `cockpit/wire.go` and `cockpit/custody.go`, exercised with the `cockpit` build tag. Contracts for cockpit state are the JSON schemas in `cockpit/contracts/`.

For the managed cockpit route, preserve `manager.Request` and `manager.Response` in `src/surfacebook/manager/uds.go`, kernel peer admission, and socket resolution through explicit configuration, `SRF_SOCKET`, then the runtime-directory fallback. The manager class set is `browser`, `desktop`, `microvm`; mediated states are `iniciando`, `listo`, `deteniendo`, `huerfana`. A failed stop can retain reservations and leases in orphan custody; inspect and stop that slot rather than treating it as reusable. The standalone Docker/Xpra shell operator is a separate route. Daemon response codes are a separate contract from CU gate process codes: inspect `RCFallo`, `RCUso`, `RCPeerRechazado`, `RCSlotOcupado` in `src/surfacebook/manager/uds.go` and `RCParada` in `src/surfacebook/manager/parada.go`; do not apply the CU never-1 convention globally.

## Network modes

`src/browserid/surface/netmode.go` defines three modes: `NetLegacy`, `NetOpen` and `NetProxied` with values legacy, open and proxied. Legacy is the shared identity network plus the egress proxy. Open and proxied each give every capsule its own network and never name the shared ones. Subnet pools are open for 172.29 slots of size 4096 and proxied for 172.28 slots of size 8192. `openImageReady` is false while the identity image predates open-mode entrypoint support, so an open start fails closed with a rebuild-required error until the pinned image is rebuilt. The pinned identity image in `src/browserid/surface/surface.go` is `opensuperficies-identity-browser-arm64:0.1.0`. The operator runs `deploy/firewall/apply.sh` as root to install the open-egress rules and write the root-owned firewall witness. Open-mode preflight consumes and validates that witness; it does not create it. The embedded IPv4 rules must match the installed rules. The pinned image currently blocks production open starts before this check. Proxied mode injects the egress proxy environment and verifies the capsule network; the proxy itself is `src/browserid/proxy` driven by `cmd/srf-egress-proxy/main.go`, which needs a registry, a policy and either an audit file or an explicit no-audit flag, and refuses wildcard listen unless explicitly permitted. `cmd/srf-relay/main.go` fails closed when no token is supplied through environment only, never through command-line flags.

## Cleanup

`detener` in `scripts/docker-xpra-surface.sh` is the normal teardown: stop the container with a 15 second timeout, remove it, remove the per-instance network, delete the run file and the container id file, then count residual processes matching the instance name. It is idempotent when nothing is active. This shell teardown suppresses Docker errors and removes its run record even if stop/removal fails; its success message and name-based residual count do not prove cleanup. Independently verify container/network absence before reusing identity or profile state. `purgar` only deletes profile locks: the caller must first establish that no live container owns the profile. A missing run file does not prove resources are absent. `purgar` handles the post-crash case without a live container: it deletes the orchestrator profile lock and any Singleton lock, cookie or socket files under the profile directory. In the capture engine, the `Stop` method on the `Capture` type seals sampling without deleting retained history; automatic TTL expiry, explicit `Reap`, or engine shutdown removes the session workspace. The `src/ramcap` and `src/cubook/capture` stores treat the guarded run directory as the only writable output and deliberately put frames only in shared memory; the storage law is checked by `scripts/cu/g_disk_frames.py` and `scripts/cu/g_disk_size.py` in the gate bundle.

## How it is tested

`QUICKSTART.md` and `AGENTS.md` give the two exact gates. `scripts/cu/gates.sh` is the full bundle: wheel build and check through `vision/build_wheel.py`, shim sweep through `vision/ramws_shim.py`, Python unit, vision, AST, bench, workload and disk gates, Go vet plus Go capture, exec and snap suites under `src/cubook/` and `cmd/srf-cu-wlcap`, `cmd/srf-cu-snap`, `cmd/srf-cu-exec` and `cmd/srf-cu-mcp`, shell entrypoint and launcher suites, hyperbook and oracle gates, contract conformance and the mutation runner. It returns 0 when every gate and every mutant is killed, 2 on usage and 5 on any failure; it never returns 1. `scripts/cu/run_suite.sh` is the shorter suite: janitor sweep, Go packages minus three live-host packages with skips for live display and the known unstable manager test, the `cmd/srf-cu-wlcap`, `cmd/srf-cu-snap`, `cmd/srf-cu-exec` and `cmd/srf-cu-mcp` packages, and the vision, AST, bench and shell suites. It also uses 0, 2 and 5. Both honour `CU_CPUSET` with default cores 10 to 14. `make test` and a bare `go test ./src/...` are not substitutes because they start a host X server and move the pointer. New code uses exit codes 0 and 2 to 7, never 1.

The monorepo parent gate, run from the repository root, pins those commands per owner. For this component it runs `cu-gates`, `cu-suite`, hyperbook, oracle, `build`, `go vet`, `go-race`, worker contracts, the cockpit package with the cockpit tag, and the offline frontend install, tests and build legs. The race leg runs `go test -count=1 -race` under `xvfb-run --auto-servernum` after excluding four packages and skipping one unstable test, on a dedicated display so the live pointer test does not fall back to the operator display. From `cockpit/frontend`, the frontend test leg runs `npm exec --offline -- vitest run` with the frontend terminal test file excluded by its name relative to that directory; the live terminal leg is separate. Worker contracts run from `contracts/worker/tests/`. The hyperbook gate is `bash hyperbooks/_tools/os/hb_os_gates.sh HB-OS-cubook` over the book described in `docs/HB_OS.md`; it rebuilds the book and the gate refuses a dirty tracked book.

## Known failure modes and limits

`docs/CU_KNOWN_LIMITATIONS.md` is the authoritative limits register; these are its live items, not promises to fix them.

- No live capsule proof is complete. Capture determinism, freezer, framebuffer memory mapping and the entrypoint identifier pin are exercised through fakes. The first live use of the uid 10001 path passed; the remaining live paths stay unproven.
- In-capsule detection relies on container markers and a none network plus the iso check; a host-network launch would also pass the marker. The launch vector is the guard.
- The Blender script scan in `capsule/astcheck/astcheck.py` and `src/cubook/mcp/astgate.go` is a lint inside the capsule, not a sandbox. It fails closed on non-ASCII outside literals, but alias and stored-callable classes outside the allowlist are still open. The real Blender path stays unwired outside the capsule with a script-exec-unwired refusal.
- Legacy live packages are skipped in the short suite: the messaging package needs a live switchboard token, the recorder spawns a host display, and the live pointer test falls back to the operator display and moves the pointer. One legacy manager test is intermittently racy on this host. The kernelbook census test is also intermittent.
- Benchmarks are unmeasured until preregistration is journalled. No success rate, cost per task or 4K 60 frames per second claim is made before the live pace cells run.
- The 60 frames per second chunk driver was fake-only for most cells; only one workload cell ran live. Four K per-chunk engine analysis is wired and fake-tested; its live per-frame cost is unmeasured. For kept cubook chunks, `ReapExpired(runDir, nowSec)` is explicitly invoked; the function does not schedule itself. Ramcap instead starts an automatic TTL deadline and reaps its session when that deadline expires.
- Chromium sandbox mode is unmeasured until the smoke decides between namespace, suid and no-sandbox; with no-sandbox the capsule is the only boundary. MIT-SHM capture is unavailable without an injected shim; capture cost has no live alternative yet. Caret, scroll and font facts for the workload scenes are pre-registered estimates until the live cells run.
- The workload item WL-7 with cursor on remains open. A launcher variable shift is fixed, but the cause among cursor theme, render-grep and cold fontconfig is undecided until the diagnostic cells run. No 4K 60 frames per second claim survives the single live 4K receipt with 33 of 60 frames published and 27 overruns.
- The x64 gate records `OpenSuperficies/go-race` as FAIL with exit 1. The first W6 leaf for this component is therefore the planned browserid surface race leaf; it is planned preparation, not an admitted fix. The same x64 result set records the Computer Use gates, the short suite and the oracle as FAIL with exit 5 and the frontend terminal leg as BLOCKED without a live fixture, so those failures do not certify the component. A prior gate log showed an infrastructure empty-string failure in the race wrapper before Go tests ran, so the wrapper itself is part of the race work.
- The identity open path is blocked: `openImageReady` is false and the pinned image `opensuperficies-identity-browser-arm64:0.1.0` predates open support. The x64 identity image needs a rebuild and the open-network check needs the open-egress witness; the help text for the surface script already warns that legacy-network failure is expected until then.
- Frames never touch disk; the gate fails an empty smoke directory rather than passing vacuously, and a 100 kilobyte per-episode cap applies. A legitimate but larger evidence set fails the gate until the launcher and disk rules are reviewed together.
