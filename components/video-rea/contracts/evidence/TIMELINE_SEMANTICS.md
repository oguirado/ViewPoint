# REA slot evidence timeline and verdict semantics

Profile `rea.slot_evidence_profile/v1`, defined in `rea.slot_evidence_profile_v1.schema.json`. Sources [CITED] are `REA_RECEIPT_FIELDS.md`, `SLOTHOST_ARCH.json`, `VISION_POOL_CONTRACT.md`, `rea.slot_request/v1` and `rea.slot_result/v1`. Status handling is specified in `STATUS_MAPPING.md`.

## Receipt and custody

The host opens `attempt` before dispatch and binds `attempt.request_id` to the provider exchange, producer and independent host artifact. It verifies provider identity and revision, implementation digest, input and output digests, and the actual supervised process. It retains failed and refused attempts. Reconciliation creates a new receipt with `attempt.reconciles_attempt_id`. The earlier receipt is immutable. The optional top-level `$comment` carries SPDX or fixture annotations and supplies no evidence.

The REA field groups are `episode`, `media`, `timeline`, `observation`, `verdict`, `slot` and `replay`. A `record` receipt uses the `original` episode role and the `reference` side of any included channel. A `replay` receipt uses `candidate`, carries `episode.parent_episode_id` and `replay`, and uses the `candidate` side. A `compare` receipt has `episode.role: comparison`, `reference_episode_id`, `candidate_episode_id`, a `verdict`, and both sides of each included channel. The `slot` fields `tool_id`, `tool_version`, `upstream_licence_id` and `source_url` identify the external tool. `attempt.slot_role` carries the provider role. The groups are optional for non-REA uses of the shared receipt.

`episode.episode_id` identifies the episode within the store. The host verifies acyclic lineage and equality of `replay.input_tape_sha256` across input-reusing episodes. A child with the same subject is a rerun. A child with a different subject is a candidate replay. `replay.seed` equals `params.seed` when supplied and is required for `seeded`. The host records controls actually exercised in `replay.controls` or the retained attempt artifacts. `exact` needs witnessed controls appropriate to the claim. A `seeded` replay supports only the scope covered by its witnessed controls and pinned policy. `distribution` requires `sample_count` and a distribution comparator. An unsupported mode abstains with `determinism_mode_unsupported`. An uncontrolled effect prevents a verdict when the declared policy depends on that effect.

## Media and clocks

`media.reference` and `media.candidate` bind `recording_sha256`, `container`, `codec`, `clock_source` and `frames`. Within a side, each `frame_index` identifies an occurrence in decoded presentation order. `pts_ms` comes from encoded presentation time in the stream time base. The host verifies the occurrence and its `decoded_frame_sha256` against the recording. When `pts_ticks` is present, the side declares `time_base` and exact rational timing governs tolerance boundaries. The comparator derives `pts_ms` by flooring the conversion to milliseconds. It must never synthesize PTS from the frame index and nominal frame rate. The policy binds the decoder and canonical raster layout. If the decoder identities differ, the host re-derives both bindings with one decoder before comparing pixels. Pixel derivatives follow the retention and `/dev/shm` rules in `VISION_POOL_CONTRACT.md`. If a side's recording is known and bound but frames are unavailable, an empty `frames` array requires `frames_unavailable_reason` and supplies no frame witness.

| `clock_source` | Use |
| --- | --- |
| `pts` | Encoded presentation time for frame pairing and for events with a verified PTS anchor. |
| `monotonic` | Event intervals with verified origin and clock custody. Cross-boot, cross-host or PTS comparison requires a retained host anchor. |
| `wall` | Attempt provenance and coarse ordering. A timing decision on a wall-clock timeline abstains with `clock_source_unsuitable`. |

The timeline declares its own `clock_source` and `origin`. Permitted origins are `episode_start`, `recording_start` and `first_input`. Use the same anchoring rule on both sides. An origin mismatch abstains with `origin_mismatch`. A clock-source mismatch without a verified retained bridge abstains with `clock_source_mismatch`. Missing or unverifiable binding abstains with `missing_clock_binding`. The host verifies the clock, origin and time base separately from the timeline digest. When `t_ticks` is present, the side declares `time_base`, the comparator uses exact rational source time, and `t_ms` is its floored millisecond projection. Integer-only observations are usable when the pinned comparator declares integer-millisecond decisions. No offset fitting or time rescaling is permitted after anchoring.

## Event and presentation checks

A timeline side declares `canonicalization: rea.timeline_digest/v1`. Compute `timeline_sha256` over the RFC 8785 canonical JSON encoding of the `events` array, keeping its order and all present event fields. Each event has `event_id`, `t_ms`, `kind` and `input_digest`. Optional `occurrence` and `t_ticks` also enter the digest when present. `input_digest` identifies the canonical causal input tape entry, excluding observation time. An event without a causal input uses the SHA-256 of empty bytes. The host rejects duplicate `event_id` within a side, decreasing source times, incoherent optional ordinals, and a digest that fails recomputation. Equal-time events retain recorded order in the array. A digest difference triggers an integrity or equivalence check according to its use. Two independently verified timelines with different digests can still match within policy tolerance.

The event policy declares the captured kind vocabulary and required coverage. Invalid event records yield `timeline_invalid`. A well-formed kind outside the compared set remains visible in diagnostics. An empty reference timeline abstains with `empty_reference` if no earlier gate supplied the reason. When a required kind or capture window is incomplete, missing events are unknown. Use `missing_reference_coverage` for insufficient nonempty reference evidence and `coverage_insufficient` for other insufficient coverage, unless an admissible divergence is already available.

Pair events by `(kind, input_digest, occurrence ordinal)`, where the ordinal is derived in recorded order for each `(kind, input_digest)` group. Event ids are witnesses within a timeline. A missing reference pair in a complete candidate capture yields `event_missing`. An additional candidate pair of an in-scope kind yields `event_extra` when reference coverage is sufficient. For paired events, delta is candidate time minus reference time. The cited profile (`replay_compare.py:8-133`, revision `0329a373`, as cited in `SLOTHOST_ARCH.json`) admits zero earliness [CITED], uses an inclusive late bound, and imposes precedence for strictly increasing reference times. Equal reference times impose no precedence. Record the parameters as `verdict.timeline_policy.early_tolerance_ms`, `late_tolerance_ms`, `late_bound_inclusive` and `equal_time_precedence`. Out-of-bound timing yields `event_early` or `event_late`. Reversed required precedence yields `order_inverted`.

A `presentation_time` check verifies the required frame occurrence pairing and PTS coverage before a decisive `pixels` check. Spatial comparison uses the paired decoded raster and the pinned spatial policy. It can report `spatial_difference`. It does not evaluate input event timestamps. A required `event_timeline` check compares event times independently of pixels. In `examples/shifted-events-negative.json`, `e2` moves from 40 ms to 120 ms [CITED fixture values]. Its 80 ms lateness exceeds the inclusive 33 ms bound [CITED fixture values]. The frame indices, PTS values and raster digests agree across sides. `event_timeline` therefore yields `mismatch` while `presentation_time` and `pixels` each yield `match`. The aggregate verdict is `mismatch`.

## Perception and pool custody

`observation.outside_capsule` is true. `observation.perception_level` records the highest level actually used in this attempt and must stay within `observation.perception_ceiling` and host grants. `none` and `cdp_atspi` take no vision lease. The host binds `observation.producer` to the witnessed tool or host producer. Per-side retained observations may carry their own `observation.sources` provenance and receipt references.

At `vision`, `observation.vision_pool_ticket` witnesses the grant. The restricted projection carries `lease_id`, the value issued by `shared/viewpoint/vision_pool.py`, and `lease_id_sha256`. The redacted projection carries the digest without the raw id. `status: granted` records the acquisition. The host verifies grant before vision work and successful release after work stops, using retained pool records. A redacted ticket alone supplies no proof of grant or release. A timeout yields an abstaining pixel check with `vision_pool_timeout` when required. An ungranted acquisition uses `vision_pool_not_granted`. A lease mismatch or unverifiable custody uses `lease_custody_unverified`. The host may use channels that already have permission and valid custody without starting vision work. Below `vision`, the receipt omits the ticket. A `pixels` check may report `abstain` to record unavailable work at that lower level.

## Verdict, controls and independence

The host resolves `verdict.policy` by `id`, `version` and `sha256`. `comparator_id` and `comparator_version` identify the host comparator. `checks` are ordered policy checks admitted to the verdict. The policy fixes required coverage, tolerance units and raster layout. Subject to the gates in `STATUS_MAPPING.md`, any bound mismatch in an admitted check yields `mismatch`. A missing or abstaining required check otherwise yields `abstain`. Every required check must run and match for `match`. A schema-valid empty check list supports only `abstain`. For a failed contrast or a gate that stops the comparison, any diagnostic observations stay in the attempt artifacts and the verdict has an empty `checks` list. `abstain_reason` is required only for `abstain`. The receipts preserve bounded `first_divergence` details and the store can page the full comparator artifact through `evidence.inspect`.

`contrast_ids` names the contrasts that ran. Their execution, activation and outcomes must resolve to retained evidence. `negative_controls` carries `control_id`, `executed`, `activated` and `outcome`, including expected controls that did not run. The control ids that ran are the ids of records with `executed: true`. A failed contrast invalidates the comparator's checks and yields `contrast_failed`. A missing, unactivated or surviving negative control blocks a match. An admitted, bound divergence survives a negative-control failure when the contrast and custody gates hold.

`oracle_independence: independent` means the expected observations were established independently of the candidate and its generator, for example by independently recording the original or using a host-qualified fixture oracle. Candidate-derived expectations, shared generated data or model output, and unproven independence use `derived_from_same_source`. That classification permits recording a comparison outcome and bars independent qualification. `independent_qualification: true` requires a host match, an independent oracle, passing required contrasts and executed, activated, rejected negative controls. Live use also requires a verified shared receipt. A clean provider exit and its own pass claim supply neither an independent oracle nor a host verdict.

## Abstain vocabulary

| `abstain_reason` | Condition |
| --- | --- |
| `control_refused`, `uncertain_outcome` | Dispatch was refused, or a possible effect awaits reconciliation. |
| `exchange_invalid`, `evidence_binding_rejected`, `custody_unverified`, `tape_mismatch` | The exchange is invalid, a binding was rejected, custody is unverified, or lineage tapes differ, respectively. |
| `slot_error`, `slot_incomplete`, `slot_stale`, `slot_budget_exceeded`, `slot_claim_only`, `slot_host_disagreement`, `stale_evidence` | Provider status or host freshness disposition specified in `STATUS_MAPPING.md`. |
| `empty_reference`, `timeline_invalid`, `clock_source_mismatch`, `clock_source_unsuitable`, `missing_clock_binding`, `origin_mismatch` | Timing preflight failed under Event and presentation checks or Media and clocks. |
| `missing_reference_coverage`, `coverage_insufficient` | Reference evidence is insufficient, or other required coverage is incomplete. |
| `perception_ceiling`, `perception_unavailable` | The needed level exceeds the ceiling, or the permitted channel cannot supply a required observation. |
| `vision_pool_timeout`, `vision_pool_not_granted`, `lease_custody_unverified` | Pool acquisition timed out, another acquisition failed to grant a lease, or lease custody failed verification. |
| `policy_undeclared`, `unrepeatable_effect`, `determinism_mode_unsupported` | The required policy cannot be resolved, an effect prevents a repeatable witness, or the comparator cannot support the replay mode. |
| `contrast_failed`, `negative_control_missing`, `negative_control_unactivated`, `negative_control_survived` | The comparison failed the corresponding contrast or negative-control gate. |

## Shared receipt adapter and conformance

`shared_receipt_adapter` is the sole binding to ViewPoint_Tools' `EVIDENCE_RECEIPT_SCHEMA`. Its published schema ID and digest are AUSENTE. While `binding_state` is `pending_publication`, `shared_schema_id` and `shared_schema_sha256` are null and `live_use_permitted` is false. A bound live receipt requires its enclosing `shared_receipt_ref` and host verification of the published schema pin. A future publication changes the adapter binding while retaining each receipt's original pin.

The examples carry synthetic digests for schema and verdict exercises. They supply no artifact custody. Live validation recomputes digests, verifies clock and producer bindings, checks required coverage and controls against the pinned policy, and verifies leases against host pool records. The conformance cases `event-and-presentation-time`, `custody-and-wrong-binding`, `oracle-independence-and-coverage`, `perception-and-pool` and `freshness-and-value-semantics` exercise those host checks.
