# ViewPoint_Medicion fixture entrypoint

Run these commands from `components/video-rea/` in the source checkout. The commands use Python 3.12 [TARGET], CPU-only fixtures, private temporary storage, and the checked-in fixture manifest. Keep `DISPLAY` unset and run one fixture scope at a time [TARGET].

| Command from `components/video-rea/` | Nominal result in `runs[].result` | Sealed contrasts |
| --- | --- | --- |
| `env -u DISPLAY python3 -B -m slot_host.measure projection` | Verified ROUTER inventory, compilation time, rows/s, and a regenerated projection digest | A changed sealed byte, missing route or divergent regenerated bytes fails verification |
| `env -u DISPLAY python3 -B -m slot_host.measure slot.inspect` | Valid static plan and admitted fixture readiness with zero launches [TARGET] | `negative` refuses an unlisted slot before fixture dispatch |
| `env -u DISPLAY python3 -B -m slot_host.measure behaviour.record` | Tape-dependent result with the captured provider `OK/0` [TARGET] and runtime evidence readback | `negative` refuses an unlisted installation. `changed` changes a tape value and its observed result |
| `env -u DISPLAY python3 -B -m slot_host.measure behaviour.replay` | Captured tape-dependent result plus retained parent and terminal evidence | `negative` refuses an unlisted parent before launch |
| `env -u DISPLAY python3 -B -m slot_host.measure error.diagnose` | `control_refusal` from a sealed `LIVE_EXECUTION_PARKED` input | `negative` omits failure evidence and yields `unknown` |
| `env -u DISPLAY python3 -B -m slot_host.measure journal.verify` | `valid`, `bound`, and `complete`, with authorized receipt readback | `negative` drops a labelled journal occurrence and reports the affected evidence ID |
| `env -u DISPLAY python3 -B -m slot_host.measure reconstruction.obligations` | `complete` against the reviewed inventory | `negative` removes a binding and identifies the outstanding obligation |
| `env -u DISPLAY python3 -B -m slot_host.measure tape.generate` | Tape and generation-log references with exact readback | `negative` refuses an unlisted workload capture |
| `env -u DISPLAY python3 -B -m slot_host.measure effect.isolate` | Paired filesystem captures and reset receipts | `negative` refuses changed scope before applying writes |
| `env -u DISPLAY python3 -B -m slot_host.measure behaviour.compare` | `match` over distinct retained episodes | `negative` changes a structured result while holding timing fixed |
| `env -u DISPLAY python3 -B -m slot_host.measure timeline.compare` | `match` with bound event occurrences and clock | `negative` shifts the required event beyond the sealed policy tolerance. `drop` removes it |
| `env -u DISPLAY python3 -B -m slot_host.measure visual.compare` | `match` over event time, PTS and decoded RGB | `negative` shifts PTS. `shift-event` shifts an event while keeping PTS and pixels equal. `change-pixel` changes pixels while keeping both clocks equal |

Use `--case CASE` to select a named contrast. Each comparator also accepts `missing`, `unknown`, and `swap` for empty, unlisted, and role-reversed references. The projected control reply is `SCHEMA_INVALID`. The standalone comparator CLI maps the empty-input `NEEDS-REFS` control to exit 14 [CITED]. The comparison policy `policy:fixture` pins the inclusive `late_tolerance_ms=33` threshold [TARGET] for event time.

Each face defaults to `--transport all`, which runs the generated ROUTER, MCP tool call, projected CLI and JSON carrier sequentially. Each transport gets a fresh request and attempt so it exercises dispatch. Use `--transport router|mcp|cli|json` for an individual sample. The MCP sample calls the generated `SlotProjector.call_tool` adapter in process. The separate `vp_rea_call` stdio service is outside this projection. The visual fixture supplies a scoped override for the published parked availability and uses the shipped visual handler with an in-process fixture lease and decoder.

`--manifest PATH` accepts an exact copy of the pinned `fixtures/manifest.json` beside its exact fixture files. The pin in `seal.py` is independent of the manifest contents. The entrypoint reads every listed file into a verified snapshot before constructing the host. Only sealed assignments can supply input to the handlers.

## JSON and metrics

The command prints one `rea.medicion.fixture_value/v1` JSON object. A checked assignment exits 0 [TARGET] with `ok: true`, `scope: "fixture"`, and a deterministic `value_id` binding the workload, build, projection and policy. Each `runs[].code` is the actual control outcome for that transport, including expected refusals. A seal or oracle failure exits 16 [TARGET] with `ok: false`, `code: "INSUFFICIENT"`, and `value_id: null`.

| Field | Meaning |
| --- | --- |
| `projection.verified_rows`, `compile_ns`, `rows_per_second`, `regenerated_sha256` | Verified inventory count, first compilation duration, computed verified-row rate and recompiled byte digest |
| `runs[].transport_ns`, `dispatch_ns`, `readback.readback_ns`, `cleanup_ns` | Transport through reply, time inside dispatch, consumer paging and verification time, and settlement time, in nanoseconds |
| `runs[].quality` | Assigned denominator, observed records and missing, duplicate, wrong, late, refused and unknown counts. An expected defect stays visible in its contrast |
| `runs[].readback` | Index digest, ordered paging measurements, and exact byte lengths, digests and references for the independently read objects |
| `runs[].witness` | Assignment, request, attempt, normalized intent, build, projection, effective policy, fixture inputs, runtime parent and confirmed terminal state. `result_sha256` hashes the canonical map from producer object names to verified byte digests. `reply_payload_sha256` identifies the projected payload independently |
| `runs[].result` | Verified fixture result or empty refusal projection. Record and replay show the decoded occurrence results and provider status |

The producer commits its temporary attempt store before the consumer's readback timer starts. The consumer verifies the authorized index and pages the retained objects. A zero-artifact face has zero object pages and bytes and a null `result_sha256`. The consumer checks runtime `attempt_evidence_record.v0.3.schema.json` and `rea_retention_index.v1.schema.json` records and verifies their parent against the sealed assignment and tape. Stateless faces recompute the expected result from sealed inputs and verify the actual projected payload. An unpaired presentation timestamp yields a timing observation when available and suppresses the pixel observation. Cleanup reconciles runtime scratch, staged files, local decoder buffers and the temporary lease.

The identity binds the ordered transport list for callable faces, the sealed assignment and inputs, the generated projection, and the relevant publication, runtime and comparator policy pins. `build_sha256` hashes the canonical manifest of measured source and schema file digests, so equivalent source trees produce the same build digest in a checkout or source archive.

## Publication boundary

This entrypoint is a source-checkout command under `slot_host/measure/`. The production operator-resource closure in `ui/tools/package.js` stages selected runtime paths outside `components/video-rea/`. The repository has no production registration for the command or its fixture trust material. The normal runtime CLI `python3 -B -m slot_host.runtime.tools mini <face> --args '<wrapper JSON>'` and comparator CLI `python3 -B -m slot_host.compare.tools mini <face> --args '<wrapper JSON>'` return their unauthenticated refusal, exit 16 [CITED], with the fixture manifest present in the checkout.

Authorized production `evidence.inspect`, the owner retention tenant and MAIN live enrolment are AUSENTE — no inventar. Fixture results establish local measurement readiness. `LIVE_EXECUTION_PARKED` applies to production. Performance adoption and live C07/C08 evidence require their Medicion and owner gates.
