# S-TORO contract semantics

This freeze specifies offline compatibility at the factory boundary. A consumer starts with the independently supplied SHA-256 of `pins.json`, verifies its raw bytes, then resolves the five schema IDs through its local map. All file paths in the manifest are relative to the asset-factory component. Deny external schema retrieval. An unrecognized ID or missing required check is incomplete evidence. A different hash at a pinned path is stale evidence.

The base is the local Git object `81b4845a12e6df6e91a2582618628a0dbfef6d5d` [MEASURED]. The manifest’s `owner_inventory` gives the path, schema or observed wire IDs and full file digest for each owner. Entries marked `frozen` matched both that object and the working bytes. At integration, all base-claiming owner rows were re-verified against the named Git object. `base-only` records the original version of an owner under concurrent development. `workspace-observation` is its observed working successor or a newly observed adapter. Neither class of historical evidence selects a runtime implementation. INT must pin the reviewed successor at integration. An `integrated` entry pins the reviewed successor at integration and must match the working bytes. An empty ID list means AUSENTE for a declared schema/wire ID in that particular file. A Python implementation path plus symbol names locates executable contracts without a standalone schema file.

The new documents use JSON Schema draft 2020-12 [CITED]. Existing slots keep their owner validation through `asset_factory.contracts.validate_slot`; the native stage retains `tools.pipeline.contracts.validate_stage`. Keep full-dialect validation separate from the kernel's restricted validator. Hash schema and documentation files exactly as stored, including whitespace. Hash raw artifacts before parsing. A canonical record digest in this protocol uses `asset_factory.core.canonical_json` (sorted keys, compact UTF-8, integers, final LF). Reject duplicate keys. Hash native receipt bytes as stored; decode the verified bytes for their fields. Test witnesses use canonical serialization so their byte hash equals `core.sha256_json`. All numeric representation choices below are [TARGET] unless an owner rule is marked [CITED].

| Boundary | Consumer and independent authority | Mandatory semantic contrast |
|---|---|---|
| Stage receipt | Join to the authenticated native stage, policy and independently established execution scope. A separate asset decision binds the subject and release state. | A successful fixture or a transport PASS with a failed/incomplete asset cannot promote it. |
| Provider request/result | Reopen canonical slot input and result, match the pending admitted request, and reopen the returned bytes under read authority. | Another candidate revision, substituted derivative, stale request digest, or fixture promoted to production refuses. |
| Artifact reference | The authorized reader opens the immutable backing within the declared lifetime, checks size and SHA-256 and keeps custody until the consumer finishes. | Alias, digest substitution, changed backing, expired lifetime or wrong reader refuses. |
| Telemetry | The recorder emits Toro-shaped events and checkpoints. Completed factory spans carry an extension. The analyser joins independently scheduled captures, raw gate evidence and effective placement. | A gap, drop, clock reversal, missing required PSI, or wrong observed niceness invalidates the timing sample. |
| Worker lease | Compare the record with current supervisor ownership, generation, clock domain, admission and resource limits. | A stale generation, expired/released lease, or missing fresh launch authority cannot authorize work. |

## Stage receipt

`af.s-toro-stage-receipt/v1` is a companion to `af.pipeline-stage/v1`. Bind the raw native receipt, stage name, ordered input and output digests, subject output digest (null when unavailable), predecessor receipt digest (null for the first stage), policy digest, execution scope, reasons and stage outcome. The native validator and release chain remain authoritative for output/evidence coverage, stage key, ordered predecessor and aggregate. Where no independently bound policy or scope exists, a caller cannot mint a production record by filling the fields. An unrecognized native scope requires explicit mapping or refusal. Map a qualified fixture/replay to `fixture`, an admitted diagnostic to `diagnostic`, and the independent production profile to `production`.

The native rc/status/verdict triples are `0/OK/PASS`, `2/ERROR/ERROR`, `3/INCOMPLETE/CANNOT_SEE`, `4/STALE/CANNOT_SEE`, `5/FAIL/FAIL`, and `6/BUDGET_EXCEEDED/CANNOT_SEE` [CITED]. A stage success can accompany an incomplete or failed asset. Supply `asset_receipt_sha256` from an independently verified decision for the same subject, and copy its actual `asset_verdict`. Without that evidence use null and `CANNOT_SEE`. A non-production scope cannot assert asset PASS. A transport judgement may be null. Only the transport receipt establishes its value. Keep negative results, reasons and raw receipts.

`tools/pipeline/release.py::build_release` copies the run verdict to the record and publish plan. `tools/publish/publisher.py` routes non-PASS destinations beneath `_review/`. Its read adapter interprets a legacy single `verdict` as transport evidence. `viewpoint/handlers.py` returns read-only `transport_verdict`, `production_verdict` and the upstream `pipeline_asset_verdict` annotation separately. A resolver success says the authorized bytes were available. The fixture oracle checks the same independent fields using a synthetic bound decision. A signed release, publisher authority or model admission cannot be inferred from this fixture.

## Scheduling intent for provider requests and stage jobs

The dispatcher supplies the same top-level scheduling fields on the provider request and on the stage job's companion receipt. Bind them to the independently admitted job before execution and when verifying its receipt. `consumer_id` identifies the consumer. `deadline_ns` is its absolute nonnegative deadline on the scheduler's monotonic clock. `priority` is an integer, with larger values preferred within the same scheduling policy. `affinity_key` groups work consumed together. For prefetchable input, `expected_order` is its nonnegative ordinal within the consumer and affinity group. Use explicit null for work without a prefetch order. All keys are required. The existing `intent_sha256` continues to bind the provider's admitted generation intent. The result's request digest also covers the scheduling fields. The native slot and stage formats retain their owner grammar.

## Provider request and result

`af.s-toro-provider-io/v1` uses `kind=request|result`. For seeded, derivative-conditioned generation, record the validated native slot request digest, request ID, provider ID and revision, exact candidate, submitted derivative, intent digest, seed, requested output schema digest and admitted scope. Rights and policy verification belong to the trusted admission path. QUAL verifies `af.qualification-rights/v1` against `core.sha256_json` of the complete `af.qualification-candidate/v1` minus its rights member, with the declared EU commercial decision. A candidate file or an inventory-only designation cannot substitute for `check_candidate`. Native `af.generate/v1` and `af.provider/v1` retain their existing grammar. Other slots continue to use their owner schemas. Exact executable candidate I/O for UniRig and MoCapAnything at the frozen base is AUSENTE.

The result references the exact pending S-TORO request digest and the native slot result digest. Match the native request ID, provider and revision and the returned artifact to the required output role and output contract. The digest of the pending request binds every context field including scope. Successful transport preserves the requested scope. An immutable reference on success requires an authorized size-and-hash reopen before exposure to the next stage. A refusal has a null artifact and retains its native rc/status and reasons; it cannot write a success artifact into this contract. A fixture run has no model-launch authority. The observed `af.trellis2-replay/v1` path and `provider-fixture-replay` scope are recorded separately from base pins. Another revision changes the binding even when the fixture bytes still match.

## Artifact reference

`af.artifact-ref/v1` names exact blob bytes as `af://sha256/<64 lowercase hex>`, with an unprefixed identical `sha256`, byte length, media type, opaque reader-authorization reference and lifetime ID. Case folding, query, fragment, tag, short digest and path suffixes are invalid. Byte length may be zero. The read service must independently authorize the caller, namespace and operation within the live lifetime, open the intended immutable backing, verify the actual stream and retain the same handle or immutable identity through consumption. A reopened digest mismatch is stale. Failure to establish lifetime or custody prevents handoff. Replacing backing after verify and reopening unchecked violates this contract.

Existing `af://<namespace>/<slug>@sha256:<digest>` locates a registry *record*. `vp.artifact_ref/v1` also carries different wire fields and supports its owner's snapshot semantics. Resolve those first under their own authority to select the intended member blob. Reinterpreting a record digest as a mesh digest is invalid. Preserve input, materialized, mapped, copied and consumer-verified bytes in telemetry. An `af://sha256/` string carries neither read permission nor a zero-copy claim. The deployable blob-reference handler belongs to ST-REF.

## Telemetry

`af.telemetry/v1` is JSONL. Capture is disabled by default. Set `TORO_TELEMETRIA=1`, set `TORO_TELEMETRIA_JSONL` to a new process-local file, and share the capture UUID through `TORO_TELEMETRIA_SESSION_ID`. Every row carries kind, session UUID, git SHA, cpuset, process ID and monotonic timestamp in ns. The wire field names, value types, checkpoint counters and copy endpoint rule follow the owner's `toro.telemetria/v1`. The factory discriminator is `af.telemetry/v1`. Events carry component `fabrica` and an operation from the frozen schema enum. A positive copy count requires both endpoints. Unknown wire counters are null. Field compatibility with the owner is distinct from admission by its live analyser, which depends on the agreed vocabulary update.

Events start at sequence 1 [CITED] per process and producer thread within a session and increment contiguously in emission order. Each process writes its own final checkpoint with record_count and ring, unregistered and invalid drop counts. Match it to the process and common session, check the count against events and reject any loss. A structural event can carry only the Toro fields. A completed factory timing span requires the closed `extension` object. It contains stage, worker and worker generation, test and request IDs, stream, spans, phase, clock, arm/pair/variant, resource counters, PSI and observed placement. Join on wire `git_sha` for the build. Wire `generation` describes the Toro operation and is independent of the factory worker incarnation. The extension's explained `copied_bytes.value` must equal the event's `copy_bytes`. Require final producer counts/flush evidence for every expected stream so missing trailing spans are detectable. A span ID is unique within a session. A non-null parent must resolve in the same session with an acyclic, temporally consistent relation. Stream order follows emission and need not nest; physical thread ownership remains explicit. Phases are queue, startup, execution, verification, teardown, and the inclusive end-to-end root. Compute elapsed time from monotonic end minus start on the same clock. Join by session/request, worker generation where applicable, test ID for test spans, build, contract pins, scheduled arm, variant and pair. The root may have a null parent, and a non-worker/non-test span may use null for those inapplicable identities.

Artifact transport records optional `extension.fallback_reason` and `extension.reason` on the event itself. The closed fallback vocabulary contains `toro_unavailable` for selection of the normal backend when Toro is unavailable. The independent `reason` field carries a failure code or exception class name, with a wire length of 1–256 Unicode code points [TARGET contract bound]. The recorder truncates longer diagnostics and uses `unspecified` for an empty diagnostic. It omits each field when it does not apply. A successful fallback therefore carries `fallback_reason` and omits `reason`.

Factory extension counters carry `value` and `absence_reason`; the branch with a null measurement requires a nonblank reason. CPU time is ns, RSS/GPU peaks and the boundary byte counters are bytes. Name the measurement source and attribution domain for CPU, RSS, GPU, I/O and PSI. Report raw counts for hits, misses and retries. A stage with no activated GPU instrument may record unknown peak with its reason. The timing gates require valid primary wall, PSI and effective entry/during-work placements. CPU, memory and I/O PSI “some” are integer ppm of stall time in the observed interval, computed from cumulative counters. `psi_pre` uses the independent pre-leg window specified in the registration. `psi` covers the span. Keep exact timestamps, PSI counter samples and child bytes in raw evidence for recomputation. The trace manifest must bind expected span/test coverage, placement and root-to-raw-evidence joins. An intact line by itself cannot establish complete capture.

Use effective niceness 15 and CPU set 0–15 [CITED]. A requested scheduling setting cannot substitute for observation. Reject a dropped or missing record, broken join, incomplete pair, wrong build/profile, invalid placement or absent required measurement. Preserve rejected traces. The manifest digest in a real capture is the digest of the *whole external pins file*. Fixture examples use an explicitly synthetic pin to avoid self-reference. ST-TRACE owns collection and whole-capture validation.

## Worker lease

`af.worker-lease/v1` names owner, provider, candidate, runtime, supervisor generation, lease and clock domain. A positive integer `lease_epoch` identifies the supervisor's grant incarnation within a worker generation. The supervisor advances the epoch on replacement, even when the resident worker stays loaded. Compare both values with live ownership before use. It records absolute monotonic issue/expiry in that domain, scheduler admission receipt hash and effective memory, swap and CPU ceilings. The owner grants `active` only after actual admission. Its validity interval is half-open. Each operation verifies current ownership, provider/candidate/runtime identity, generation, clock, deadline, resource ceiling and independent current rights/admission. A single-use launch permit is consumed by the existing launch authority exactly once. The same lease never renews it. A change of clock epoch or generation invalidates old leases.

Only the owner may transition an active lease to `released`, `invalidated` or `crashed`. Record the terminal time and reason. Terminal records are historical; they cannot be used for fresh work. Confirm drain and resource release against the scheduler before replacing ownership. Unknown cleanup outcome fences the generation until independently reconciled. Recovery establishes a fresh generation and admission after proving prior ownership retired. Expiry or file disappearance alone is insufficient. `af.scheduler-request/v1`, `af.scheduler-observation/v1` and `af.scheduler-receipt/v1` keep their owner semantics. ST-LEASE implements transitions and recovery.

## Fixture and compatibility protocol

The manifest embeds the corpus under `semantic_fixtures` and pins its complete factory canonical JSON, including case names, records, authority data, patches and expected refusal reasons. Each case starts from a fresh deep copy. Apply top-level `replace` members, overlay `extension_replace` members inside the extension, remove listed `remove` keys, then apply `witness_replace` members to the independent fixture context. Validate the selected schema, then the cross-record and reopened-byte rules. Success means fixture conformance. Source payloads are synthetic, and their byte lengths, clock values and scopes serve only as test vectors. A production adapter obtains its witnesses from its owner and trusted pending state. The submitter cannot supply that authority by including “witness” fields in a message.

Use the frozen baseline owner files in the inventory and preserve native consumers for old data. A change to a normative schema, fixture or policy needs a reviewed new pin set and a compatibility verdict. This pre-admission repair supersedes the initial draft under the existing family IDs. Select the complete reviewed pin set before reading a record. Previously frozen draft rows require their original manifest. After admission, incompatible wire changes need a new ID. No product hook is installed by this freeze.
