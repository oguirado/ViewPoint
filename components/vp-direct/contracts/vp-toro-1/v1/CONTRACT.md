## Recorder and joined capture

Ship a native recorder in every build. X-I measured **1,310.11 ns** incremental cost per complete Python scope [MEASURED: X-I_REPORT.md], against **41 ns** [TARGET]. Python may enter the native recorder at a scope or batch boundary. Use a guarded disabled path, bounded preallocated per-producer SPSC rings, single-writer cursors, monotonic timestamps and asynchronous JSONL export to a fresh private file opened exclusively with mode `0600` [TARGET]. Take both boundary timestamps and perform all required ring writes without heap allocation, formatting, blocking or per-element FFI on the hot path. Maintain shutdown order: stop admissions, resolve outstanding scopes, flush rings, publish final checkpoints and close each sink.

Propagate one `TORO_TELEMETRIA_SESSION_ID` to all participating processes. `candidate.schema.json` keeps the upstream `toro.telemetria/v1` fields, constraints and native operation vocabulary. The added component `viewpoint` uses the **18** named operations [CITED: STRATEGY_VP_TORO1.md]. The table describes observations. Export only values with a declared field and approved origin. Use registered numeric status codes and checkpoint counts for fallback, refusal, drops and trial disposition. Keep timing and privacy-gap evidence private.

| Operations | Contract boundary |
|---|---|
| `capture`, `digest`, `privacy_check`, `serve` | Frame arrival, geometry, epoch, digest outcome, immutable generation, changed extent, fence result, enqueue/service wait and handed-off bytes. `serve` spans request through response. VServe internals are **AUSENTE — no inventar**. |
| `observe`, `infer`, `plan`, `act`, `verify`, `receipt` | Correlate proposal, first eligible protected observation, inference, decision, action, verified effect and committed receipt. Record refusals, errors, timeouts and stale results. Keep the synchronous completion boundary. |
| `admit`, `refuse`, `wake`, `sleep`, `drain` | Record request and admission/refusal, generation, lease, outstanding work and terminal disposition. Keep the existing wake metric alongside wake-to-first-protected-result-and-receipt. |
| `record`, `rewind_restore`, `encode` | Ordered block sequence, custody, immutable snapshot identity, input/output lengths, codec completion, restore validation and epoch transition. |

Key emitter attribution by `(session_id, process_id)` in the session manifest, with expected SHA, cpuset, permitted components and producer thread roster. Require non-null, exact SHA and cpuset matches for qualification. Expand Linux affinity ranges and serialize both rows and the emitter manifest as ascending, unique decimal CPU IDs separated by commas, without spaces or leading zeroes. Protocol control ranges describe host placement. ViewPoint and Toro may have distinct revisions and affinities declared per emitter. Each capture sink holds rows from its declared emitter. A joined reader may interleave the sinks while preserving each producer’s local order. A thread sequence begins at the first declared value of `1` [TARGET] and increments by one per event. Compare clocks within each producer and across joined start/end boundaries using the same verified monotonic clock domain. Thread-grouped output can interleave timestamps across producers.

Track producer calls, admissions, drops, and exported sequences by producer. Admit exactly one event per accepted event-recording call, reconcile complete scope boundaries, and match every exported event against its producer. Final producer counts must be known and reconcile to emitter `record_count`. Reject drops, gaps, duplicates, torn JSONL or duplicate JSON keys, absent producers, rows after final close, missing close, invalid clock intervals, foreign rows and attribution mismatches. A `LATEST` policy skip increments the separate frame-skip counter. It cannot offset a telemetry loss.

A null optional counter requires an entry in the private joined cause ledger with exactly `session_id`, `process_id`, `thread`, `sequence`, `field` and `cause`. The identifiers must match the registered session and validated event, `field` must be one of `logical_bytes`, `copy_bytes`, `dram_bytes`, `nvme_bytes` or `wait_ns`, and `cause` must be `unavailable` or `not_applicable`. Reject unknown entries, fields, duplicate keys, arbitrary extensions and free text before writing the ledger and again when joining it. The cause ledger is the only sidecar payload covered by the contract. The conformance fixture wraps cause entries with synthetic roster and clock evidence. Never replace null with a measured zero. An unavailable mandatory integrity counter invalidates qualification. An unavailable mandatory endpoint or mechanism counter cannot support promotion. Positive `copy_bytes` carries an allowlisted source and destination. Export only registry-derived opaque identifiers, counters and verdicts. Reject pixels, paths, URLs, OCR/AX text, exception text, credentials, cookie values, window titles and content-derived digests in telemetry, cause entries and diagnostics.

## Bulk seam and lifetime

`bulk_v1.h` declares the ViewPoint-local C ABI and descriptor layout for CPU blocks on 64-bit Linux [TARGET]. The Toro reference ABI remains independently pinned in `sources.json`. Negotiate ABI version and all layout sizes via `vp_bulk_get_api_v1`, then validate the result before open or dispatch. The caller owns its function table and descriptor arrays. The provider owns the context and backing resources. The header defines concurrent access, exact batch counts, fd ownership and release ordering. A release call addresses one exact lease and block or batch calls cover multiple data elements.

| Rule | Contract |
|---|---|
| R1 | Route frames, weights, artifacts, snapshots and large reads through the internal bulk interface. Default `VIEWPOINT_TORO=off` makes no provider probe, load or open. `observe` runs normal with telemetry. `on` verifies the pinned provider before load, then requires a successful bootstrap and table validation before `toro_open` or dispatch. Identity, loader, symbol, bootstrap and ABI/table validation failures fail closed. Only confirmed library absence or an explicit pre-custody `toro_open` refusal from the verified provider selects normal, with the corresponding bounded status. Post-acquisition failure follows R8. |
| R2 | Carry a contiguous payload separately from width, height, row stride, format and epoch. Validate offset plus length and geometry without overflow, check supported format and minimum stride, and verify backing size before mapping. END carries no payload and closes its epoch. Reject old frames and stale tickets after END. Vision uses LATEST with explicit skip counts. Recording uses ORDERED. |
| R3 | Store immutable snapshots, model files and rewind states by full SHA-256 and expose `af://sha256/<hex>`. Before dispatch, authenticate the authorized root, consumer, lease and declared intent independently of the digest. Verify the digest before restore. Changed bytes require a different identity. |
| R4 | Require consumer, monotonic deadline, priority, affinity/group and applicable expected order before dispatch. Validity flags distinguish absence from measured or declared zero. |
| R5 | Keep CDP, AT-SPI and orchestration in Python. Move data through the block/batch ABI. Replay the same vectors across implementations and count crossings. |
| R6 | Python uses `memoryview` or `mmap`, and Rust borrows a mapped slice for the lease. Apply the readable memfd recipient policy below at the S5 boundary before sending. Verify the received fd before mapping. A local borrowed view has no transferable address. |
| R7 | `load/query/unload` expose executable/model identity, generation and lease epoch. Invalidate on restart and reject expired leases. |
| R8 | Each successful local borrow requires one explicit successful release, including after in-flight timeout or child death. Break fences new dispatch and new views immediately. Existing local views and borrowed fds remain valid until their holders retire them and release the exact lease. Drain completes after local release, attributable work and remote custody settle. Ignore late replies for effects and receipts and reconcile their custody in the broken session. Cover both observed `LifecycleError` drain cases. Use stable action identity and idempotent commit. |
| R9 | Join both producers with verified capture evidence and a pinned, accepted reader. Reject drop, gap, missing close and foreign-event mutants. Measure instrument overhead separately. Status is candidate-compatible. |
| R10 | Run capped offline builds and tests. For live work use private X displays at or above `:90` [TARGET], private DBus/AT-SPI and disposable loopback CDP. Clean up only registered PIDs. Refuse `:0`, operator profiles/cookies, unbounded execution, raw devices, host installs, `sudo` and `drop_caches`. No GPU is requested. |

### Readable memfd recipients

| Recipient verified by S5 | Staged pixels | Current `CLEAR` bound to this recipient and exact frame |
|---|---|---|
| Registered S5 capture-stage process (`s5_capture_stage`) | Eligible under the staging controls below | Eligible |
| Registered S5 capture-staging checker (`s5_capture_staging_checker`) | Eligible under the staging controls below | Eligible |
| Any other authenticated recipient, including an unrelated checker | Retain inside S5 | Eligible |
| Unauthenticated or mismatched peer | Retain inside S5 | Retain inside S5 |

Before either arm in `arms/Z.json` transfers readable bytes, require current S5 capture authorization and authenticate the expected peer on the private channel by `SO_PEERCRED` against the registered recipient and its `(owner, trust_domain)`. Staging roles are assigned by S5 registration. Staging requires zero retention, tracked custody and verified settlement. A shared UID or a self-declared role confers no staging privilege. Bind S5 `CLEAR` to the exact payload, recipient, session, lease, generation, epoch, observation and privacy revision. Authorize the full readable extent, including row-stride padding, and reject any prior-frame tail. Recheck state before transfer. If these gates fail or the frame requires recall or overwrite-scrub after delivery, retain it inside S5 as a `ram_ref`.

Validate the ticket and ancillary message against the registered session and expected descriptor before mapping. Require close-on-exec on sender duplicates and receive with `MSG_CMSG_CLOEXEC`. Reject missing, extra, truncated or mismatched rights and close every received fd on rejection. Before mapping require `F_SEAL_WRITE`, `F_SEAL_SHRINK` and `F_SEAL_GROW`, exact readable extent, checked geometry and bounds, and matching generation and epoch.

Local release ends API access only after local users are done. An `SCM_RIGHTS` transfer gives the recipient its own descriptor and mappings. Sender close, expiry, release or later `HUMAN_NEEDED` cannot recall these or any copied bytes. The recipient must drop views, unmap and close its descriptors, then acknowledge settlement. After recipient death, verify OS cleanup for the tracked process and any allowed custody before accepting settlement. Keep charges until verified settlement. For sealed handoff the receipt attests fd and mapping settlement. The existing overwrite-and-verify scrub receipt applies to the S5-retained path where scrub is required.

At Q, run the full own suite in `off`, `observe` and `on`, including provider absence, refused open and ABI mismatch. Compare consumer deliveries, privacy decisions and receipts. Record test-provider and real-provider evidence under their own identities.
