# Incident Runbook: Sovereign Surface Hypervisor (srfd daemon and cockpit)

Scope: what to do when the shipped daemon, its client, the census or the cockpit misbehave, as they exist on disk on 2026-09-20. The exit-code table is in `guias/ng/GUIA-OPERACION-HIPERVISOR.md` (section 7); capacity in `guias/ng/GUIA-CAPACIDAD-HIPERVISOR.md`. The frozen v1 runbook `guias/RUNBOOK-INCIDENTES.md` is read-only input: its 14-row triage matrix (`guias/RUNBOOK-INCIDENTES.md:7` to `guias/RUNBOOK-INCIDENTES.md:20`) names rc 1, 3, 4, 6, 7 and 69 only and has no rc 126 row; the v1 table that runs 0 to 9 is in the v1 operation guide (`guias/GUIA-OPERACION-SUPERFICIES.md:47` to `guias/GUIA-OPERACION-SUPERFICIES.md:56`), which has no rc 126 row either. Both describe the v1 Docker CLI workflow.

Rules. Every command below is followed by a marker. `[ran: rc N, <log>:<line>]` means the command was run in this session, its raw output is in `evidencia/v2/u22/comandos-runbook.txt` or `evidencia/v2/u22/comandos-runbook-2.txt`, and the cited line is the `rc=N` line of that run. `[not run: <reason>]` means the command was NOT run and is taken from source, so it has not been observed working. Nothing in this runbook touches the operator's displays `:0` or `:1`, and none of the commands starts a daemon. Every `file:line` citation and every marker is re-read by `evidencia/v2/u22/verificar-guias.sh` (operation guide, section 10, lists exactly what it compares).

## 1. First minute: who answered, and what does the code mean

1. Which command returned the code, and where does that command put it? The same integers mean different things for the engine (`srf-motor`, WAL), the daemon wire (`srfd`, `srf`, `srf-mediacion`) and the campaign instrument (`campana.sh`), and the producers report them through different channels. The table is section 7 of the operation guide; in one line per producer: `bin/srf-motor`: JSON only, the engine code is `.rc` of its JSON (or the `rc: N` text line) and its process status is 0, so `$?` reads 0 even for rc 6 (`cmd/srf-motor/main.go:335`, `evidencia/v2/u22/comandos-runbook-2.txt:3`, `evidencia/v2/u22/comandos-runbook-2.txt:11`); `motor/cdp_runner.py`: exit status and JSON, the v1 runner exits with its code (`motor/cdp_runner.py:485`) and with `--informe` also writes `rc` to a JSON file; `bin/srfd`: exit status; `bin/srf`: exit status and JSON, `--json` prints the refusal with its `rc` on stdout; `bin/srf-mediacion`: exit status; `bin/srf-capsula`: exit status; `bin/srf-wal-verify`: exit status, its own 0, 1 and 2, never an engine code; `bin/srf-puertos`: exit status and JSON; `scripts/ng/campana.sh`: exit status and JSON; `newton jaula`: exit status, 126 when the cage could not be built (`/home/user/Documentos/newton-shell/main.go:877`).
2. rc 6? One lookup: `bin/srf-wal-verify --rc-map` [ran: rc 0, `evidencia/v2/u22/comandos-runbook.txt:72`] prints `RC 6: EN_DUDA` (`evidencia/v2/u22/comandos-runbook.txt:68`) and `RC 1: NO_ENVIADO` (`evidencia/v2/u22/comandos-runbook.txt:63`). EN_DUDA means dispatched with the state unknown and the quota possibly charged: never retry, seal it and escalate (`PLAN-CAMPANA-OPENSUPERFICIES-V2-NEXTGEN.md:1063`). NO_ENVIADO means nothing was sent and the key is free (`src/orchestratorbook/wal/desenlace.go:15`).
3. After a crash, intentions that were dispatched but never resolved are recorded by recovery as EN_DUDA with RC_AMBIGUO (`src/orchestratorbook/wal/recuperacion.go:161`), and EN_DUDA is never re-attempted automatically (`src/orchestratorbook/wal/desenlace.go:19`).

## 3. Procedures

A. Daemon unreachable (row 1). Confirm the socket the client uses (`src/surfacebook/manager/uds.go:113`); check that the file exists and is a socket owned by your uid with mode 0600 (`src/surfacebook/manager/uds.go:157`); if it exists but nothing answers, the next `srfd` start replaces a stale socket and refuses a live one (`src/surfacebook/manager/uds.go:179`).

B. rc 6 or EN_DUDA: do not retry. Record the slot, the key and the time; hand it to the operator. EN_DUDA is never re-attempted automatically (`src/orchestratorbook/wal/desenlace.go:19`), and recovery records unresolved keys as EN_DUDA (`src/orchestratorbook/wal/recuperacion.go:161`).

C. rc 126. Stop dispatching, run `scripts/ng/campana.sh residuos` and keep its raw output, then escalate. Do not clean up destructive host state on your own.

D. Shutdown that reports live capsules. `srfd` exits with an error naming the slots that are still live and keeps the journal (`src/surfacebook/manager/uds.go:488`); stop those slots through the client, then start the daemon again so the lessor can rebuild its epochs from the journal.
