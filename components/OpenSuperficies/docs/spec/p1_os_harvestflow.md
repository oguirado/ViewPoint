## A-result, A-completion and integrity

New requires an independently created aggregator with authorized task/attempt/lease bindings, host sink, finite projection budget and frozen harvest configuration. Identity is computed through the existing aggregator C3 canonicalizer; the joining sink calls the original sink's Merge then invokes the real aggregator Ingest before allowing the harvest pipeline to reserve/publish. Each accepted repro observation has a stable attempt-specific stream and monotone sequence. The aggregator independently checks source identity and allowed provenance. Equal canonical bytes merge; a digest collision with unequal canonical bytes remains in separate buckets. Authenticated witness sets are unioned.

For every authenticated and collected attempt, Flow.Run separately calls Aggregator.Ingest with AttemptReceiptRef in a stable receipt stream, whether or not the attempt yielded a finding. Repetition at the same sequence is idempotent and changed bytes are refused. No publication ACK is promoted into application success or verified cleanup. The original host receipt, normalized 0/2–7 exit, nullable native raw gate exit, SHA256, capacity-held status and usage are exposed in A-result. A-completion preserves Accounted, Closed, DoneSuccess, Pending, CapacityHeld, SubmittedAttempts and ExitCode. Accounted=true does not imply DONE_SUCCESS: any failed shard prevents it.

Costs remain nullable. Only an explicitly labelled microUSD harvest unit may become aggregator cost_micro_usd; missing and unconvertible costs remain null with reason AUSENTE. Host proof or native exit fields that are missing stay null, not zero. A publisher reservation is immutable; a missing ACK is reconciled by query, not resent. Flow serializes concurrent calls so the shared pipeline and aggregator streams cannot double-submit.
