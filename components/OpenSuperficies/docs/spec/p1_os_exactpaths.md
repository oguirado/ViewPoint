# P1 OS — exact-path Muse source (Area A)

## Contract and interface

`musesource.BuildExact(queue []byte, cfg musesource.Config) (wire []byte, sidecar []byte, err error)` is a **read-only preflight**. It validates the *entire* queue's registered files and live builder leases **before** invoking the unmodified legacy `Build`. It returns no bytes on any refusal. It never creates registration, reserves a seat, writes an output, executes a gate, sends a request or publishes a result. Producer dependencies: none beyond `bridge/integration`.

The separate sidecar has **emission order** `schema`, `source_manifest`, `exact_write_paths`, `sha256`. The schema is `proto1.source-exact/v1`. `source_manifest` is the original `w8-muse-source-frozen-v1` frozen-field record, normalized only where the exact, at-most-two-seat emitted wire changes the emitted/pending totals and `wave_sha256`. `exact_write_paths` contains an ordered list of the registration's **individual exact file grants** for each *emitted* task ID; a pending task is fully checked but is not granted/emitted. The `sha256` is lower-case hex SHA-256 over the **workerbridge.Canonical** representation of the other three fields (sorted UTF-8 keys, compact JSON, no HTML escaping, integer-only numbers), not of the sidecar as emitted. That sidecar is **evidence only, not authority**.

`BuildExact` serializes its Muse wire as `[]w8muse.Item`, preserving `task_id`, `attempt`, `objective`, then optional `patch_path`. `ValidateWave` checks the final bytes. In contrast, legacy `Build` emits `[]map[string]any` and thus orders wire keys alphabetically; its behavior is left unchanged. **PRODUCTION_DEFECT (outside grant):** legacy wire ordering differs from the documented `w8muse.Item` field order (`src/w8wave/musesource/source.go:373-380`, `:395`; `src/w8muse/driver.go:18-23`). The new API formats its own wire correctly and re-hashes it; this note does not purport to repair the legacy API.

## Validation, authority and refusals

`BuildExact` checks its `Config` and three-tab-field queue using the existing validators (`src/w8wave/musesource/source.go:128-195`); individual briefs remain bounded and read by `Build` (`:344-360`). For every task, including one pending beyond the admitted prefix, it reads the real registered `task.json`, the real `expected/<id>/<attempt>.json`, and the shared live `ledger.jsonl`, then calls **the existing `checkRegistration`**, not a test stub. This binds builder role, surface, repository, base commit, attempt, branch, expiry, expected record, canonical task hash, and matching granted lease events (`:204-272`). A checksum plus inode snapshot of each registered file is compared again after generation, and the registration/ledger checks run again before returning any bytes. A concurrent replacement detected at either boundary refuses all output; no claim of kernel-level transactional filesystem snapshot is made.

Each entry in `allowed_write_paths` must be a unique, canonical, relative **repository filename** with `[A-Za-z0-9_.-]` components, no `.`, `..`, `.git`, wildcards, backslashes, slash suffix, or directory path. The two registered output names, `result_path` and `report_path`, pass the same checks and cannot alias any grant or each other. A duplicate grant across queued tasks is also rejected. Existing path components are checked with `Lstat` to reject symlink, non-directory ancestor and directory-as-file broadening; missing eventual output leaves are permitted because a grant may authorize a new file. Queue output targets are canonical absolute local file names whose existing path components must not be symbolic. Repository anchor is derived from `<root>/.wavemind/bridge` or `<root>/bridge`; symbolic roots and unknown layouts fail closed because `Config` has **no `RepositoryRoot` field** (`:40-53`). A registered relative filename is not inferred from a filesystem wildcard/directory.

Invalid registered write/output paths yield `workerbridge.Reject{Class:"input", Code:2, Detail:"E_WRITE_PATH: ..."}`. This **does not introduce any new exit code** (`src/w8wave/musesource/source.go:61-87`, `src/workerbridge/json.go:24-32`). Invalid/unavailable registration or changed lease remains code **4**, as the source's real validator specifies. An open wave, an unavailable seat, exhausted configured credits, or no remaining two-seat concurrency yields the existing code **6** and its `EN_DUDA` detail (`src/w8wave/musesource/source.go:362-369`). The configured `MaxInFlight` is retained, with an additional exact-wave two-seat cap; original `Build` is unmodified.

## Finite budgets and evidence plan

Budget facts at this source revision: queue at most **256 KiB / 64 lines**, brief at most **64 KiB**, lease ledger at most **16 MiB** (`src/w8wave/musesource/source.go:26-30`). `Config.MaxInFlight` remains within **1..64** (`:153-157`), while this exact-wave API emits at most **two concurrent seats**. Header/manifest limits use the existing `w8muse.MaxHeader` rather than an invented constant (`:276-279`, `:410-411`). `MaxWaveTasks` is **AUSENTE**; no new producer initializer or external transport is assumed.

`TestProto1Exactpaths` (owned `src/w8wave/musesource/proto1_unit_test.go`) builds a real temporary bridge, real canonical task hashes, expected record and append-only lease events. Green cases are first: two calls with deterministic byte identity, strict decoder and literal ordered-wire oracle, unchanged frozen field hashes, independent SHA-256/canonicalization oracle, one- and two-credit admission, and simultaneous read-only calls released by a channel barrier with a fixed-seed registration order. A filesystem-backed read-only sink spy snapshots contents and checks no persistence; `BuildExact` exposes no injectable publisher. No X server, docker, network, app launch or frame files are required.

Must-FAIL cases with **exact normalized code**, nil source/sidecar and unchanged fixture state: trailing `dir/` (2), wildcard (2), parent traversal (2), duplicate file (2), symlink escape (2), invalid pending third job (2), attempted existing-directory broadening (2), backslash (2), absolute file name (2), noncanonical doubled separator (2), altered live lease ledger (4), changed base pin (4), registered directory output (2), and unavailable/full/open wave (6). Refusals must not allocate/release/send/publish: none of these producer APIs are invoked by `BuildExact`. This is source-only evidence, not host seat evidence.
