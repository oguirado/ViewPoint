`govbridge.ToAuction`, `ToPool`, `Add` and `SumCertificate` convert by **named uint64 fields** and reject per-dimension overflow; never cast signed values, reinterpret structure memory or guess CPU/memory units. `Config` explicitly supplies all four nonzero ceilings and independent finite wave/seat capacities (hard maxima **64 waves** and **2 concurrent seats**). Zero ceilings or missing finite capacity are unavailable, not infinity.

**A-source ordering:** (1) host creates immutable wallet/epoch/certificate evidence, (2) actual `auction.Select` and `VerifyFull` identify a feasible proposal, (3) `ManagedPool.Stage` freezes the complete award/epoch and checks the exact member resource sum, (4) `pool.Reserve` checks its own version and ceilings, then the adapter checks its independently serialized ceilings and seats, (5) only then `auction.Commit` calls the live trusted `HostPort.Reserve`, (6) host verifies the *same ID* and generation 1 using `CheckCurrent`, (7) pool creates a charged preparing entry. Neither staging nor selecting creates a lease. Any missing host authority refuses admission. A failed or malformed host reply triggers an independent `VerifyNoHold` attestation; if the host cannot prove non-allocation, the adapter retains an **indeterminate shadow hold** (charged in its counters even though the pool could not create an entry). Such a shadow hold has no speculative release path; a trusted host reconciliation mechanism is required. A success is not assumed from an untrusted echo.

**A-completion ordering:** (1) `pool.Claim` produces the next generation after a real cold-ready path, (2) host independently binds the current lease generation and `ManagedPool.BindGeneration` verifies it with `CheckCurrent`, (3) dirty/STOP/expired/quarantined work keeps its hold, (4) only a full pool cleanup sequence yields a *local* `pool.CleanupProof`, (5) `HostPort.CheckCleanup` must authenticate *its own independent cleanup record*, exact reservation, generation and release key (it must not accept `proof.Verified` as a trust anchor), (6) `ManagedPool.Release(ctx, ID, proof, key)` uses one matching key and invokes the pool's release transition, which calls adapter `Release`, (7) the adapter rechecks live host reservation and calls distinct `HostPort.ReleaseHold` with its generation and key, (8) only on confirmed success are the charged vector and active seat returned. An unknown host release response leaves the hold charged; retry requires host-idempotent release semantics. Same-key replay returns nil without a second host release, different-key replay refuses. `ManagedPool` deliberately does not expose its underlying keyless `*pool.Pool` or raw adapter to callers.

The adapter's balance snapshot reports actual admission attempts, successful admissions, host releases, live seats, held resources and released cumulative totals; released totals use exact decimal big integers to avoid overflowing across completed waves. A canceled request before host admission is rejected without consuming resources and its uncharged staging slot is discarded; `CancelStage` only removes uncommitted proposals. Cancellation after a successful transaction does not implicitly revoke a hold.

## Refusal taxonomy (checked, not optimistic)

- **Code 2** (`pool.Fault`): malformed ID/vector, missing context/key, swapped CPU and memory dimensions, illegal wave/seat configuration. `auction.ErrInvalid` stays typed as provided by the verifier.
- **Code 4** (`pool.Fault`): any missing ceiling/capacity or resource/seat/wave backpressure; never reinterpret zero as unbounded. `auction.ErrHold` remains a distinct typed upstream error.
- **Code 5** (`pool.Fault`): conflicting/stale immutable award versions, id/generation mismatch, unauthorized/stale host reservation or release-key conflict. Preserve `auction.ErrConflict`, `auction.ErrDenied`, `auction.ErrOverflow` through `errors.Is` when emitted by producers.
- **Code 6** (`pool.Fault`): independently unverified teardown or indeterminate host release, *without* refund of reserved resources. Host errors are wrapped with `errors.Join`, not swallowed. Pool-specific code can be retrieved via `pool.CodeOf` (`pool.go:330-336`); producer sentinels remain distinguishable (`auction/types.go:15-22`, `auction/queue.go:114-126`).

## Outside-grant boundaries and PRODUCTION_DEFECT observations

- **PRODUCTION_DEFECT / integration gap** (`src/w8wave/pool/pool.go:62,253-270`): the keyless `pool.Governor.Release(id, Vec)` cannot itself bind a release key or cleanup generation. `ManagedPool` constrains the caller surface and the adapter stages a host-verified permit, but an independently accessible bare pool pointer would bypass that control; never publish the bare pool port as an untrusted API. No producer change is within this write grant.
- **PRODUCTION_DEFECT / recovery gap** (`src/w8wave/auction/types.go:279-306`): `auction.Commit` can validate the returned echo but supplies no atomic undo/reconcile operation for a host that allocated capacity before returning a forged/invalid receipt or an ambiguous transport error. The trusted host MUST give rollback-free/atomic refusal or durable conservative fencing. `HostPort` specifies this as a precondition; the adapter keeps an indeterminate shadow hold until reconciliation if `VerifyNoHold` fails, but a concrete durable implementation and recovery receipt are **AUSENTE**, not implemented by the in-memory spy.

The adapter intentionally invents none of them: they remain explicit host integration prerequisites. Host policy for unaccounted observed usage (HOLD versus conservative charging) is **AUSENTE** and must be decided by trusted host policy; no free-capacity assumption is safe.
