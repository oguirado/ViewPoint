For D5, the key invariant is append-only: 8–16 agents can reuse a common repository/system prefix only when the provider sees an identical rendered prefix, an eligible cache boundary was previously written, and the request reaches a serving location where that entry remains available. A shared repository, session ID, or semantically equivalent prompt is not sufficient. After agents diverge, they can still share the common trunk, but their subsequent tool histories and reasoning state form separate branches. developers.openai+2
The second critical distinction is accounting: newly generated thinking is charged as output; preserved thinking may subsequently become billed input, potentially at a cached-input rate. Provider usage fields differ substantially, so a generic “input + output + reasoning + cached” sum will double-count tokens on several APIs. developers.openai+3
Below, “current” means the official documentation retrieved for this answer, checked against the October 19, 2026 query date. Historical measurements are explicitly labeled. I did not run an 8–16-agent experiment myself.

Exact boundary mechanics:
cache_control on a block writes one cumulative-prefix entry at that endpoint.
Reads search backward for entries previously written; they do not automatically cache arbitrary stable content discovered along the way.
Each breakpoint checks at most 20 positions, including itself.
On the Claude API, consecutive 
tool_use blocks count as one lookup position, as do consecutive 
tool_result blocks.
Up to four breakpoints are available. Top-level automatic caching uses one slot and moves to the last eligible block. platform.claude
For D5, place one explicit breakpoint immediately after the shared repository/instructions, before agent-specific content. Use another boundary—or automatic caching—for each agent’s growing history. A sole breakpoint after a changing timestamp/assignment can repeatedly write a nonreusable prefix. platform.claude
Other consequential rules:
Default TTL: five minutes; optional one-hour TTL.
TTL runs from request start, not response completion. A four-minute response can leave only about one minute before a five-minute entry expires.
Cache availability begins after the first response starts; simultaneous cold requests cannot be assumed to share the first write.
Longer-TTL boundaries must precede shorter-TTL boundaries.
Isolation is workspace-level on the direct Claude API, Claude Platform on AWS, and Foundry; the docs describe organization-level isolation for Bedrock and Google Cloud. platform.claude
Minimum cacheable length is model-specific. Current examples include 512 tokens for Opus/Sonnet/Haiku 5.5 and Fable 5.1; 1,024 for Sonnet 4.6; 2,048 for Opus 4.7; and 4,096 for Opus 4.5/4.6 and Haiku 4.5. Below minimum, caching is silently skipped. Partner deployments require checking their own support matrix. platform.claude
Writes cost 1.25× for five minutes or 2× for one hour. Reads normally cost 0.1×, with current exceptions of 0.05× for Opus/Sonnet 5.5 and 0.025× for Fable/Mythos 5.1. platform.claude

6. D5 implementation rules and acceptance tests
These are design deductions from the contracts above, not additional provider guarantees.
Recommended bus and context policy
Freeze a versioned shared prefix: repository snapshot, tool schemas, application instructions, and relevant request settings.
Put agent identity, worktree paths, and assignments after the shared boundary wherever the harness permits.
Prewarm deliberately where supported; verify usage before launching the full fan-out.
Keep separate immutable histories per agent, including their opaque reasoning.
Append versioned bus deltas or bounded digests; never overwrite an old digest or tool result.
Compact at explicit epoch boundaries, preserving the stable trunk where the API/harness allows it.
Treat cache misses as normal operational events, not correctness failures. developers.openai+3
A shared bus does not make all its deliveries cache-free. If every one of 𝑁 agents contributes 𝑑 new tokens per round and every agent consumes all contributions, newly delivered bus input is approximately:𝑁2𝑑
tokens per round, before metadata and protocol overhead. A fixed-size aggregate of 𝑏 tokens instead gives approximately 𝑁𝑏 fresh delivered tokens. These are delivery-volume derivations, not measured provider bills; cache reuse of subsequent historical replay is a separate term.
Measure the actual 8–16-agent workload
Run both cold and warmed tests at 8 and 16 agents, holding model snapshot, harness version, authentication route, processing region, and corpus fixed.
Include these controlled variants:
Identical shared prefix, different assignments.
Timestamp or worktree path before versus after the shared boundary.
Immutable appended digest versus rewritten earlier digest.
Preserved reasoning versus intentionally omitted reasoning in a test environment.
Stable versus shuffled tool definitions.
Warm versus expired cache.
Before versus immediately after compaction.
Native subagent versus exact conversation fork, where supported.
Log provider usage verbatim, plus prefix/version hashes, boundary locations, TTL, cache/isolation key, request start, first event, first visible text, completion, retries, and actual billed cost. These distinguish routing misses, boundary misses, hidden-thinking latency, and context rewriting—the failure classes identified in the official docs and measurements. developers.openai+3
