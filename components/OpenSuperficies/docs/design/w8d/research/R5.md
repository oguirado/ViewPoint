For D6, the key distinction is identity: production systems deduplicate crash manifestations, coverage observations, patch candidates, and evaluation jobs using different keys. None of these automatically establishes that two observations have the same underlying bug.
The canonical production mechanisms are normalized stack/report signatures in ClusterFuzz and syzbot, and coverage-bitmap novelty filtering in AFL. LSH is a documented scalable near-duplicate retrieval technique, but the sources below do not establish it as the standard deduplicator in ClusterFuzz or syzbot. Likewise, AST differencing is a useful foundation for patch fingerprints—not a canonical crash-deduplication algorithm supplied by SWE-bench. blackhat+4

2. Stack-frame normalization: ClusterFuzz and syzbot
ClusterFuzz: exact signature first, approximate grouping second
The clearest primary account is Arya and Chang’s ClusterFuzz: Fuzzing at Google Scale, Black Hat Europe 2019, slides 30–32. It specifies:
Immediate deduplication using the tuple 
(Crash type, Crash state, Security flag).
Crash state formed from the top three “interesting” frames.
Inclusion of debug/release assertion information.
Exclusion of inline frames and common library/debug functions.
Special treatment for OOMs and timeouts, ignoring the stack trace.
A slower second stage using Levenshtein distance to group similar crash signatures. blackhat
A schematic representation—not a literal serialization format—is:text
crash_key = (
    crash_type,
    select_interesting_frames_and_assertion(normalized_report),
    security_flag
)

exact_lookup(crash_key)
then, separately:
    similarity_grouping(crash_signature)
The important algorithmic point is selection and normalization, not the hash primitive. Hashing raw stderr would preserve irrelevant variation; hashing only the faulting function would lose distinguishing context. ClusterFuzz instead constructs a deliberately filtered “crash state,” which its official glossary defines as the stack-derived deduplication signature. google.github+1
Open-source implementation: google/clusterfuzz. Treat the three-frame rule above as the documented 2019 design rather than an immutable guarantee for every subsequent parser and configuration. blackhat+1
