# W8 amendments for the design review (relayed by visual-qa-0, 2026-10-19)
A1 PREBUILT PER-COMMIT ENVIRONMENT IMAGES (operator idea, refined by visual-qa-0):
1. One versioned environment recipe per target repo (e.g. .wavemind/env/Dockerfile or setup.sh: deps, toolchains, Rust build, repo installed) = single source for (a) the Jules environment setup script, (b) the OS image builder, (c) W8 worker capsules. Pass in Jules => pass in a capsule.
2. Build LOCALLY (host aarch64 GB10; GitHub runners mostly x86_64; no Actions minutes on private repos). Trigger: bridge/integration moves (auto_sync / auto_ingest hook) -> image <repo>@<sha> on host, keep last N, tag published in the receipt.
3. Worker capsules boot from <repo>@<sha>: Muse tasks start in seconds with deps/builds ready.
4. Images hold code and toolchains only: never secrets, never frames (STORAGE LAW). Gates: same recipe -> same image digest for the same sha (reproducibility); must-FAIL recipe leaking a file from ~/.config is refused.
Note: Jules VM cannot be exported; the shared recipe is the equivalent.
Conductor note: any image build on the host is an operator-visible act (prior campaign rule: no image build without operator OK); the review must name where that approval is recorded (standing approval for the builder service vs per-build).

A2 PHASE 2 MINI-ORCHESTRATOR (operator idea, refined by visual-qa-0): after the single-capsule worker works.
1. No Kubernetes; build essentials into the OS Go control plane: pods = worker capsules (docker now, microVM later); scheduler = queue + admission by cgroup RAM/CPU budget (newton-ia.slice, free-RAM floor); liveness = Erlang/OTP-style supervision tree (restart policy per task, give up after N); job = one wave of tasks in the shared Web Bridge contract.
2. In-capsule agent (test runner, resource watch, result streaming) Go first; Rust only if measured hot path; control plane Go.
3. Communication = OpenSwitchboard (scr-sbd-* pieces: conectar, conferencia, buzon, actuar, vigia-enjambre). DEFAULT independent workers posting structured results to a mailbox + one aggregator; ROOMS only when sharing improves outcomes (a finding re-targets related workers); structured speech acts (finding, repro, affected, status), never free chat; vigia-enjambre flags stuck/duplicate workers for reassignment.
4. Acceptance: N capsules in parallel, N measured at the knee (start 8); 0 cross-capsule leakage; findings deduplicated by repro hash; per-wave total cost and wall time; must-FAIL: a worker flooding its room is throttled by the vigia.

A3 NESTING + CONTROL CHANNEL + LEASE MODEL (operator preference, checked by visual-qa-0):
1. Docker outside (packaging, network, filesystem, cgroup quotas), microVMs INSIDE that container for kernel isolation; several microVMs may share one container (firecracker-containerd / Kata pattern). Host: /dev/kvm present (crw-rw---- root:kvm), kvm loaded, aarch64 -> container needs /dev/kvm passthrough + aarch64 guest kernel + rootfs from the per-commit env recipe (A1).
2. Headless tasks talk to each microVM over vsock (or serial) with structured receipts; UI tasks add xpra in that microVM and wender-agent operates it.
3. Lease model shared with wender multi-window (visual-qa-0 MESH JQ1 C9, wender WP1-06): per-target lease, one coordinator, broker/aggregator with provenance, per-target STOP/failure with supervised restart. Scheduler API compatible: lease_id, target_id, state, receipt (one agent drives N microVMs or N browser windows through one abstraction).
4. Gates: kernel isolation (guest cannot see host processes or mounts); /dev/kvm the only device passed through; N microVMs per container at the knee; must-FAIL: guest reaching the host network outside its allow-list is blocked.
