## Contracts

### Path preference and selection

The exact preference tuple is `("api", "ax", "coordinates")`. The module describes these labels as app API/MCP, AX/DOM action, and coordinates, respectively (`wender/act/actor.py:4`, `wender/act/actor.py:10`). This is an ordering of labels offered by the caller; discovery of available executors is **AUSENTE** (`wender/act/actor.py:14-20`).

`choose_path(available)` first evaluates `set(available)`, then visits `PATHS` in tuple order and returns the first member present in that set; if no member matches, it returns `None` (`wender/act/actor.py:14-20`). For ordinary string labels, duplicates and the iteration order of `available` do not change the chosen preference. Conversion happens before selection, so an iterable is consumed into a set before any result is selected (`wender/act/actor.py:16-19`).

There is no normalization, validation against a schema, special case for a single string, or error wrapper. Unknown labels have no matching tuple entry and are ignored. A bare `"api"` is converted into its characters rather than treated as the label `"api"`; `None` and unhashable members fail through the underlying set conversion. These are static consequences of the `set` call, not observed execution results (`wender/act/actor.py:16-20`).

Selection does not acquire a lock, call an executor, check whether a target is actionable, or advance to another path after an execution failure. Its complete body ends at the return of the selected label or `None`; dispatch and fallback-on-failure contracts are **AUSENTE** (`wender/act/actor.py:14-20`, `wender/act/actor.py:54-55`). The inspected tests assert that `{coordinates, ax}` chooses `ax` and `{api, ax}` chooses `api`; they do not demonstrate a working path executor (`tests/test_layers.py:44-46`, `tests/test_layers.py:55-57`).

### ActorLock: primitive, identity, and lifecycle

The module states a single-actor rule for a surface and says that readers never take the actor lock (`wender/act/actor.py:5`). The implementation creates one `threading.Lock()` per `ActorLock` instance and initializes a public `holder` attribute to `None` (`wender/act/actor.py:31-33`). There is no surface parameter, shared registry, process coordination, or target-to-lock mapping in this class. Therefore the implemented exclusion is per instance; the association of one shared instance with one surface is a caller responsibility whose mechanism is **AUSENTE** (`wender/act/actor.py:28-50`).

`acquire(who)` attempts the underlying lock with `blocking=False`. If it cannot acquire, it raises `ActorBusy`, a subclass of `RuntimeError`, with the message template `surface already driven by %r` populated from the current `holder`. If acquisition succeeds, it assigns `who` to `holder` and returns the same `ActorLock` instance (`wender/act/actor.py:23-24`, `wender/act/actor.py:35-39`). There is no queue, blocking wait, retry loop, deadline, or cancellation parameter in this method (`wender/act/actor.py:35-39`).

The supplied `who` is stored without validation or comparison. It may be `None`; the stored value alone consequently cannot distinguish an unlocked instance from an acquired instance whose caller supplied `None`. Reacquisition does not gain special treatment for the same actor identity; the underlying nonblocking lock is attempted again (`wender/act/actor.py:33`, `wender/act/actor.py:35-38`). `holder` is descriptive metadata, with no accessor or identity protection in the inspected class (`wender/act/actor.py:31-50`).

`release()` takes no identity argument, clears `holder` before calling the underlying lock's `release()`, and has no explicit return value. Repository-level actor ownership validation and special handling of an unlocked lock are **AUSENTE** (`wender/act/actor.py:41-43`). A successful call therefore returns `None`; a failure from the underlying primitive is not caught by this method (`wender/act/actor.py:41-43`).

`__enter__()` only returns `self`; it does not acquire. `__exit__(*exc)` calls `release()` and then returns `False`, so a body exception is not suppressed when release succeeds. It does not inspect the exception arguments or catch a release failure (`wender/act/actor.py:45-50`). The acquisition-before-entry usage present in the inspected test is `with lock.acquire("a"):`; that test then expects another acquisition to raise `ActorBusy`, and acquires again after leaving the context (`tests/test_layers.py:48-53`). Bare entry and release misuse require review; see Findings (`wender/act/actor.py:41-50`).

Action input schema, parameter validation, supported operations, target identity, waits, retry policy, action outcome categories, post-state verification, irreversible gating, and integration of the single-actor rule into dispatch are all **AUSENTE** at the execution entry point (`wender/act/actor.py:54-55`).

### Existing perception helpers relevant to future actions

The AX matcher tries `L0_EXACT`, `L1_STABLE`, `L2_NAME`, `L3_VARIANT`, and `L4_UNIQUE_ROLE`. L0 and L1 initially restrict candidates to the recorded role, normalized name, and ordinal. A supplied exact fingerprint is compared at L0; a supplied stable fingerprint is compared at L1. However, when `fp_exact` is missing or `None`, a candidate at that role/name/ordinal can be returned immediately as `L0_EXACT` with `established=True`, without comparing a recorded fingerprint (`wender/perceive/ax.py:265-279`). Later levels relax the match through same-name candidates, explicit name variants, and a unique role (`wender/perceive/ax.py:280-295`).

`level_allows_irreversible(level)` is exactly membership in `("L0_EXACT", "L1_STABLE")`; L2, L3, L4, and a missing level return false through that expression. It receives only the level string: it does not check the selected node, `tie`, candidate count, score, `established`, context, disabled state, or action classification (`wender/perceive/ax.py:298-300`). The matcher itself can return a selected node even when its diagnostic `tie` is true (`wender/perceive/ax.py:257-263`). There is no call to this helper, the matcher, or an authorization interface in the actor stub (`wender/act/actor.py:54-55`). Treating the helper as a complete executor authorization check is therefore **AUSENTE**.

The available STATE builder marks a node actionable when its role is in the caller-supplied actionable roles and its `disabled` attribute is not the exact string `"true"`. That is a STATE classification, not an executed action precondition in ACT (`wender/state/schema.py:43-44`, `wender/state/schema.py:65-67`, `wender/act/actor.py:54-55`). Browser perception can supply integer CSS-pixel border boxes through `DOM.getBoxModel`; missing backend IDs, caught box-model failures, and absent or non-eight-value border quads do not create a box entry (`wender/perceive/browser.py:26-41`). The builder then uses `boxes.get(id)`, allowing a null box (`wender/state/schema.py:50`, `wender/state/schema.py:67`).

Viewport extraction exposes integer width, height, scroll offsets, document dimensions, and device pixel ratio in parts per million. No conversion from that data into an actual action coordinate exists in `execute` (`js/inpage/viewport.js:8-10`, `js/inpage/viewport.js:21-31`, `wender/act/actor.py:54-55`). Browser `page_state` assembles AX, page identity, viewport, boxes, and hashes through successive calls; it supplies no action transaction token to ACT (`wender/perceive/browser.py:45-58`, `wender/act/actor.py:54-55`).

## Determinism and hashing

For ordinary string labels and an unchanged `PATHS` tuple, path selection depends on set membership and fixed tuple order, not the input's order. It has no hash output, receipt serializer, or operation identity (`wender/act/actor.py:10`, `wender/act/actor.py:14-20`). Lock acquisition depends on whether the primitive can be acquired at the instant of the nonblocking attempt; deterministic winner selection, scheduling, and fairness contracts are **AUSENTE** (`wender/act/actor.py:35-39`). `holder` stores the caller's object without conversion into a stable identifier; diagnostic output uses its representation (`wender/act/actor.py:33`, `wender/act/actor.py:37-38`).

ACT itself computes no action hash, pre-state hash, post-state hash, or idempotency key; those contracts are **AUSENTE** (`wender/act/actor.py:10-55`). The following existing perception/state mechanisms are evidence inputs a proposed verifier could use; none is called by the actor stub (`wender/act/actor.py:54-55`):

## PROPOSAL — executor contracts for design review

**Every requirement in this section is a PROPOSAL.** The code supplies a path preference, a per-instance lock, perception helpers, and an execution stub. It does not implement the proposed behavior below (`wender/act/actor.py:10-55`). Proposed policy values, operation schemas, and numeric wait/retry budgets remain **AUSENTE**; this review does not assign them.

### PROPOSAL: common transaction and single-actor contract

Define one explicit surface identity and one shared lock mapping used by API, AX, and coordinates dispatch. Acquire that lock nonblockingly before mutation, keep it through outcome verification, and release it on every terminal path. A busy result should stop the competing transaction. Readers should retain the independent read behavior stated by the module. Define ownership and cleanup rules that cannot accidentally release another actor's transaction. This proposal fills the gap between the stated surface-wide rule and the current per-instance primitive with no surface key or ownership check (`wender/act/actor.py:5`, `wender/act/actor.py:31-50`).

Define an action envelope that binds the surface, selected path, operation/parameters, preconditions, expected postcondition, reversibility classification, and actor identity. Validate it before dispatch. Define outcomes distinguishing a rejected precondition, an operation known not to have been sent, a verified success, and an operation with an uncertain effect; do not automatically choose a weaker path after an uncertain mutation. The present selection helper only chooses a label and the stub has no action validation or outcome model (`wender/act/actor.py:14-20`, `wender/act/actor.py:54-55`).
