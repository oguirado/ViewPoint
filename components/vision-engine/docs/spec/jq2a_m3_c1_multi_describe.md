# JQ2A M3 C1 — bounded, per-window temporal description

## API and implementation

`vadapt.multi_describe` exports the canonical **frozen** `Handle(kind, canonical_id, generation)`, `WindowFrames(handle, epoch, frames, frame_seqs, dpr_ppm)` and `WindowDescription(handle, epoch, frame_seqs, descriptors, regions, error)` in exactly that field order. `describe_windows(items, *, workers=1, params=None, runner=None, out_dir=None)` returns one description **in input order**, even if worker results arrive in reverse order or one stream fails. A `WindowDescription.error` is `None` on success; a nonempty `E_M3_*` code explains refusal/failure. A completely malformed item with no trustworthy handle/epoch/sequence is rejected with `WindowInputError(ValueError)` rather than a fabricated receipt.

Each result's `descriptors` is a tuple of immutable serialized, per-frame `visioncore.desc.TILE_DTYPE` records (`bytes` produced by `VisionRun.tiles[k].tobytes()`); `regions` is a tuple of per-frame tuples of the sealed core's region dictionaries. The original submitted handle, epoch and local sequence are preserved. These are physical-pixel core regions, **not** an invented AX/DPR fusion output.

Input validation rejects unsupported kinds, empty IDs, invalid generation/epoch, nonpositive integer DPR, empty/misaligned/non-monotone local frame sequences, mismatched `FrameRef` identity/epoch/sequence/geometry/digest, inconsistent geometry within an epoch, non-`uint8` or non-C-contiguous RGB, and overlapping slices. It accepts duck-typed `FrameRef` instances with `.rgb` and the documented metadata, without importing other adapter components. Every validated array is copied to an owned, C-contiguous, read-only NumPy buffer **before** executor admission. No shared-memory borrowing or lifetime-dependent descriptor view escapes.

The grouping key is `(handle.kind, handle.canonical_id, handle.generation, epoch)`, never frame size alone. For multiple nonoverlapping slices of one stream in the same call, the adapter orders slices by `frame_seqs` and passes their concatenated sequence to the core once; results are split back by original submission index. Different incarnations and geometry epochs start fresh temporal histories. A conflicting geometry epoch or overlap is an explicit error rather than silent state reuse. Histories do not survive across separate `describe_windows` invocations: the caller must supply the predecessor history it wants compared; indefinite implicit frame retention is deliberately not offered.

Per-stream execution invokes `visioncore.pipeline.analyze(MemoryFrameSource(...), workers=1, cpus=[], out_dir=None)`; **parallelism is across independent streams**, not inside their sequential S0–S4 classifier. Worker results carry submission IDs, so `.map` delivery order cannot rewrite identities. The default `ThreadPoolExecutor` pools are persistent and bounded: at most eight worker-count variants and 36 total worker threads (effective per-call workers capped at eight). Injectable `runner.map(fn, batches)` can simulate reversed completion and partial executor failure. A raised runner error marks only unfinished work; completed work is not resubmitted. No transport/focus/actor metadata lock is held during compute. No process, physical display, or file artifact is used by this module.

## Invariants and source coordinates

- **INV-M3-1** — `_admit` checks identity, DPR, local order, RGB schema and owned RAM before `_pool` or `runner.map`; `describe_windows` assembles tagged results into the original indices. See `vadapt/multi_describe.py` `_admit`, `_error`, `describe_windows`. The positive/reversed-completion and bad-schema controls are in `tests/test_jq2a_m3_c1_multi_describe_implementation.py`.
- **INV-M3-2** — `_batches` keys on the full target incarnation **plus** geometry epoch and never dimensions alone. `_run_batch` presents the sealed pipeline one private chronological history, so neither tile predecessor equality nor S2 classification can bleed between windows. The adversarial same-size, generation/epoch, and split-stream tests distinguish the grouping-by-size mutant.
- **Fixture and S5 timeline** — The same-size contaminated-history oracle places A's synthetic frame numbers immediately before B's unchanged local numbers. The concatenated `frame_nums` are strictly increasing as required by sealed S5, while the original foreign-predecessor inequality remains asserted.
- **INV-M3-3** — `_run_batch` always uses sealed-core `workers=1` for each stream and returns owned `tobytes()` snapshots. Only independent stream scheduling changes with `workers`; the tests compare serial tiles and regions for counts 1, 2, 3, 8 and 64 (capped). Injected fake runners test reverse completion and death; a RAM snapshot test mutates M4 caller buffers after admission.
- **Core coordinates read at `bridge/integration`** — `visioncore/parallel.py` `describe_many` (ordered S1 reuse and worker range); `visioncore/pipeline.py` `analyze` (full S0–S4 sequential classification and optional out-dir write), `VisionRun.tiles`, `.regions`; `visioncore/frame.py` `Frame` and `MemoryFrameSource`; `tests/test_parallel.py`, `tests/test_fx2_f7_j2_parallel_describe_many_schema_and_workers.py`, `tests/test_jq1_a3_parallel_worker_schema_range.py` for offline regression expectations.
