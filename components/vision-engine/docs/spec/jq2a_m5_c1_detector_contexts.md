# JQ2A M5 C1 — per-window contexts (eval-layer implementation)

## API and source binding

The task's proposed Handle(kind, canonical_id, generation) and ChangeResult(handle, epoch, settled, claims, ops) are frozen dataclasses, with precisely those positional fields, in eval/v2x/per_window_detector.py. PerWindowDetector(*, gm=None, fl=None, veto=None) accepts a GM module implementing estimate_global_motion and consensus_tiles, an FL module exporting FlickerTracker and (preferably) update_with_ops/ops_scope, and a **factory** for per-grid veto instances. Defaults: eval.v2x.gm_bands_hv, eval.v2x.fl_v3, eval.v2eval.postpass.BaselineFlickerVeto. update(handle, tiles, rgb, *, epoch, frame_seq) returns a copied, read-only baseline-shaped structured claims array; reset_window(handle) discards that target's state. Foreign records with the same Handle fields are accepted (duck typing); no cross-repository import is introduced. The ops dictionary contains GM and FL operation counts; None means an injected implementation did not expose a verifiable count, **not zero work**.

Source coordinates at explicit bridge/integration: eval/v2x/gm_bands_hv.py:9-47,538-620 and gm_constellation.py:22-73 use context-local GM counters; fl_blinkprior.py:1-40,80-228 supplied the legacy global tracker counter; fl_v3.py:1-43,88-260 defines the baseline-only veto; eval/v2eval/postpass.py:54-137 computes owned eager RGB descriptors and two-frame veto history, with overlay at 32-51,172-285. This task changes only owned eval modules; not visioncore/change.py, visioncore/pipeline.py, or other sealed core implementation.

## Invariants

**M5-1: local histories.** Registry lookup holds a short mutex; every canonical Handle has a distinct serial lane. Its tracker, veto instance, previous owned RGB/luma, eager hash snapshots, last local frame sequence, grid and bounded GM content-pair cache are never shared with another Handle. Higher epochs, frame-sequence gaps, and explicit reset_window start fresh state for that Handle alone. Stale epochs, non-increasing local sequences and same-epoch geometry changes raise DetectorInputError before advancement. Other target lanes continue.

**M5-2: real operation counts.** The original FlickerTracker automaton and charged operations are otherwise unchanged. Source increments now use ContextVar instead of a shared OPS integer. ops_scope installs a fresh count via a token and restores that token in finally; update_with_ops executes inside contextvars.copy_context(). The detector runs independent GM and FL calls in separately copied contexts, so their counts cannot race with sibling calls. The legacy reset_ops and dynamic OPS interface remain available in the caller's own context.

**M5-3: provenance and precedence.** RGB and baseline S2 tiles are copied before any plugin. Fresh lazy_xh=False descriptors are computed from real padded RGB **before** the veto adapter captures its own history. FL consumes these eager content hashes, not lazy zeros or copied JITTER hashes. Only an explicit shape-checked mask of baseline class-4 FLICKER candidates can change baseline FLICKER to CHANGED. Positive FL never overwrites verified GM or original baseline MOVED. Unclaimed tile fields remain identical to baseline. If the independent GM estimator refuses real motion, the wrapper does not invent a vector.

**Readiness/freshness.** settled is false until three consecutive unchanged **transitions** backed by adjacent local frame sequence numbers, with no GM/FL claim, no veto, no baseline CHANGED/MOVED/FLICKER/DRIFT and byte-identical owned RGB. This API receives no timestamp or receipt and cannot assert wall-clock freshness. A gap, epoch change, missing evidence or invalid plugin output never creates successful settlement. Counter None is not a score.

Claim precedence is verified GM, positive FL and then the original baseline (with explicit baseline-only veto); all decisions use deterministic integer evidence. No calibration or guessed motion scores. The bank performs perception only: it does **not** implement focus, action admission, action receipts, ownership or cross-target scheduling. If a capsule and its child screen refer to the same destination, upstream registry/scheduler must use the same canonical actuation resource, not two leases. The registry metadata mutex does not span plugin computation; same-target calls serialize on their private stream lane.

## Prerequisites, limits and gate honesty

Dependency order: **identity and streams → ownership and perception → readiness → scheduling and Godot → scorecard**. Proposed TargetRecord, Observation, FrameRef, ActionRequest, Receipt, leases, stream tokens, tickets, WindowFrames and WindowDescription are **not integrated** by this eval-only patch. CDP/X11/Xvfb/Godot dispatch and prerequisite gates are **AUSENTE**; do not use this patch as an integration-dispatch green light. Core motion-publication starvation documented at docs/spec/jq1_a2_s2_flicker_veto.md:69-75 remains unrepaired because sealed core is outside task ownership. A GM abstention never becomes a fabricated success. Host throughput, live integration, wall-clock settle freshness, full benchmark coverage and threshold calibration are AUSENTE. Target lanes retain metadata after reset_window to preserve exclusion against in-flight updates; long-lived registry eviction requires separate ownership work.

The offline tests in tests/test_jq2a_m5_c1_detector_contexts_implementation.py exercise production public paths and typed injected GM/FL fixtures: simultaneous copied FL contexts with a barrier, solo/interleaved replay, frame gaps, RGB provenance, exact A-B-A return, and GM-first motion claims. No expectedFailure or no-op success is passing evidence. Actual VM test results and missing runner dependencies belong in the outbox report.
